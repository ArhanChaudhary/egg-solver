Reproduced safe-public-API failures

Every reproduction below calls the baseline library without an unsafe block. Both x86 AVX2/BMI2 and the portable backend failed. Debug checks sometimes abort at the unsafe precondition; release-profile Miri reports the underlying UB. Miri ignores optimization levels, so these are interpreter results, not execution of optimized native instructions. No Miri UB checks were disabled.

The original [255;32] malformed-cube probe completed without a diagnostic. It was not evidence of general safety: the [4;32] case reaches an out-of-range rank-table lookup. Inputs and complete diagnostics remain in the probe directory.

Reproduced search-publication failure

A new tracing regression test reproduced another UB diagnostic under Miri seed 15. finish_build published jobs, then passed &Inner to trace_build. Another worker finished those jobs and entered build, obtaining &mut Inner while the tracing argument remained protected. Miri rejected that overlap. The test enables real search tracing and adds a test-only scheduling delay immediately after publication; the delay changes scheduling, not the ownership protocol. This reproduction used the candidate before the tracing fix, rather than the untouched baseline used by the four public-input probes.

The correction completes tracing before the Release publication. start_sort also no longer receives &mut Inner as an argument: that function-entry borrow could otherwise stay protected across publication of its tasks. Its local setup borrow now ends before publication. The latter is a manual finding, not a separately reproduced diagnostic.

Evidence: diagnostic, saved pre-fix source, reproduction metadata.

Review coverage and remaining limits

Reviewed the public constructors feeding unchecked indexing; Memory ownership, alignment, slice lengths and mutation contracts; coordinate ranges; cached solver pointers; the lane stack's MAX_TARGET < MAXD bound; move masks; job sorting indices; shared-search claims, publication, buffer ownership and mailboxes; parallel runner callbacks; platform vector/assembly entry points; and the WASM allocator and pointer-bearing ABI. This is a manual review, not a formal exhaustive audit of every execution or dependency.

The custom parallel runner accepts safe Fn + Sync callbacks. Current internal callers either read disjoint/immutable slices or allocate work with atomic counters, so duplicate callback IDs were not established to cause UB. Its exactly-once behavior is a separate API-contract concern.

WASM threads use a lifetime extension for a borrowed callback and wait for all workers before returning. Current shipped WASM builds abort on panic; unwinding or changes to the join protocol require a fresh audit. Foreign callers must respect pointer lifetime and immutable-input requirements.

Tests remain finite. Native AVX-512/assembly, actual mmap/SysV operations, WASM host behavior, dependency code and all possible weak-memory executions are not covered by a universal proof. Full source-bound native/backend and Miri validation must finish before integration. Existing ignored tests must remain explicitly listed, not counted as passes.
