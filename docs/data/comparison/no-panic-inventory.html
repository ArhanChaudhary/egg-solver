4. Enforcement

  • Clippy, at every crate root (src/lib.rs, src/main.rs, src/bin/{bench,gen,solve}.rs, build.rs, wasm/src/lib.rs, wasm/build.rs, benches/kernels.rs): #![cfg_attr(not(test), deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::unreachable, clippy::todo, clippy::unimplemented))]. cfg(test) builds (unit tests) and tests/, examples/ (separate crates without the attribute) are not linted. check.sh's clippy runs (x86, scalar, aarch64, wasm32 targets, and -p cubeopt-wasm on both wasi targets) enforce it.
  • No lint flags assert!: tests/no_runtime_panics.rs scans the shipped sources (src/, build.rs, wasm/src, wasm/build.rs, benches) and fails on assert!, assert_eq!, assert_ne!, panic!, unreachable!, todo!, unimplemented!, .unwrap() or .expect( outside
    • test code: any item, statement or field after #[cfg(test)] / #[cfg(all(test, ..))], to the end of its { .. } block (or its ;/,),
    • compile-time code: const/static initializers (from = to ;, e.g. const _: () = assert!(..), static BUILD_DIR) and inline const { .. } blocks (not const fn bodies). Comments, strings (incl. raw) and char literals are blanked first, so text in them never matches. A second test checks the scanner itself on a sample (comments, strings, constants, cfg(test) modules, fields and functions; finds a runtime assert_eq! and .unwrap()). check.sh runs it as its own step right after cargo fmt (and it also runs with the other tests). It is a Rust test, so it needs nothing but cargo (no Python on the laptop/CI).
  • debug_assert! stays allowed (not in release builds).
  • Not enabled: clippy::indexing_slicing (≈300 sites, most in in-range loops and hot kernels; per policy, no get_unchecked sprinkled to satisfy a lint) and clippy::arithmetic_side_effects (thousands of sites). Sections 2-3 list where the remaining implicit checks are.
