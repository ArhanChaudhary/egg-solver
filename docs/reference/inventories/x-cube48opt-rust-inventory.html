xcr: cube48opt-rust technique inventory vs cube-opt

Historical snapshot. Its source, timings and pending statements belong to the recorded experiment, not the current checkout. Documentation home.

Reference: github.com/2017YANR02/cuberoot.me solver/experiments/cube48opt-rust at 1effb34 (2026-11-05), fetched to /data/agents/xcr/src/cuberoot.me/solver/experiments/cube48opt-rust. Ours: ~/cube-opt main 18c4a66.

Paths in cube48opt-rust are relative to its folder. "lanes", "share", "solver", "tables", "coord" and "simd" mean our src/lanes.rs, src/lanes/share.rs, src/solver.rs, src/tables.rs, src/coord.rs and src/simd.rs.

What it is:

  • A Rust reconstruction of Chen Shuang's cube48opt1..9 WASM. It was rebuilt from the decompiled WAT ("functions 36-44, 47", src/search.rs:1-8) and checked against the WASM's behaviour.
  • It is MIT for the cube48opt-derived parts and GPL-3.0-or-later for the nissy H48 port (LICENSE, SOURCES.md). The crate as a whole is GPL-3.0-or-later (Cargo.toml:7).
  • It has three backends:
    • Opt1-9: the original cube48opt tables h48prunNN.dat, read from the WASM generator's output, plus a small-memory.bin snapshot dumped from the WASM.
    • Opt10: their own EO10 table with a 1 KiB header, generated by a native generator.
    • H0-H10: nissy-core's h48hN files.
  • Around the Rust sources are about 30 research notes and Node/TS benchmark guards. Every number in them comes from a Mac (M5 Pro, 16 threads, WCA 1000, a single unpaired pass) or a shared Linux Xeon (4 threads).
  • The author gave permission to copy code (user, 2026-11-05). No win came out of it, so no adopted code is delivered. The two negative branches carry "adapted from cube48opt-rust … with the author's permission" credits (search.rs:710-739 reject_backward_coset; the projection idea of search.rs:1261-1275).

Two subagent readings of the notes were cross-checked against the code. The corner96 line is section F; the Opt8-11/H10 notes are spread through the tables.

Verdict codes:

  • HAVE: we do the same.
  • BETTER: we do more, with a measured gain.
  • GAP: missing and applicable.
  • N/A: missing, but it does not apply.
  • MEASURED-NO: missing, measured, and it doesn't pay. The measurement is ours unless it says "theirs".

M1. Backward coset certificate (C9): MEASURED-NO

Implemented in lanes.rs (stream kernel) as other_moves &= QUARTER_TURNS when a moved-side child value (lookup or corner bound) is exactly remaining + 1 of the node (child over by 2). Branch neg/xcr-backward-coset (on 0b5b5a6), $P/xcr/neg-backward-coset.patch.

Why nothing: it is redundant. A later sibling gM′ has D_H(gM′) ≥ D_H(g) − 1 = its own remaining depth; with exact codes 1..3 its own table value already says so, and its child_node removes the same half turns (C3). Only code-0 (inexact) values can differ, at remaining ≤ base, where few nodes are. Theirs agrees: Opt10 nodes +0.13% (the −2.2% time was one unpaired pass), Opt8 WASM nodes −0.0086%, time +18.9%. Not timed (node counts decide).

M2. Max over stabilizer frames (C14): MEASURED-NO

Upper bound of the gain: Solver::index takes, among all stabilizer frames of a self-symmetric corner class, the one with the largest table value, with every extra frame's value free. Branch neg/xcr-projection-max, $P/xcr/neg-projection-max.patch.

Benchmark facts (for f1)

See $P/xcr-bench-entry.md. Points that affect running it fairly, all handled there:

  • 18-thread cap for one-cube search (native_parallel.rs:13).
  • 4K pages natively: tables in a malloc'd Vec, no madvise. Use hugeshim thp/hugetlb.
  • Opt10 file format: a 1 KiB header and minima ≤ 10, while cube48opt10's raw table stores 15 in unread minima. Handled by a loader-only shim on f1's file; the bytes are proven identical to their official table by SHA-256.
  • No x86 prefetch in the official Opt10 feature set: screen the pf build.
  • CUBEOPT_SIMD=auto picks AVX2: AVX-512 is equal here.
  • Opt10 loads ~4 min per run.
