# cube48opt-rust technique inventory

Reference: [github.com/2017YANR02/cuberoot.me](https://github.com/2017YANR02/cuberoot.me) `solver/experiments/cube48opt-rust` at 1effb34 (2026-11-05), read from a local copy. Ours: egg-solver (then named cube-opt) main 52ab88f.

Paths in cube48opt-rust are relative to its folder. "lanes", "share", "solver", "tables", "coord" and "simd" mean our `src/lanes.rs`, `src/lanes/share.rs`, `src/solver.rs`, `src/tables.rs`, `src/coord.rs` and `src/simd.rs`.

What it is:
- A Rust reconstruction of Chen Shuang's cube48opt1..9 WASM. It was rebuilt from the decompiled WAT ("functions 36-44, 47", `src/search.rs:1-8`) and checked against the WASM's behaviour.
- It is MIT for the cube48opt-derived parts and GPL-3.0-or-later for the nissy H48 port (`LICENSE`, `SOURCES.md`). The crate as a whole is GPL-3.0-or-later (`Cargo.toml:7`).
- It has three backends:
  - **Opt1-9:** the original cube48opt tables `h48prunNN.dat`, read from the WASM generator's output, plus a `small-memory.bin` snapshot dumped from the WASM.
  - **Opt10:** their own EO10 table with a 1 KiB header, generated by a native generator.
  - **H0-H10:** nissy-core's `h48hN` files.
- Around the Rust sources are about 30 research notes and Node/TS benchmark guards. Every number in them comes from a Mac (M5 Pro, 16 threads, WCA 1000, a single unpaired pass) or a shared Linux Xeon (4 threads).
- Its author gave permission to copy its code (2026-11-05). No win came out of it, so no adopted code is delivered. The two negative branches carry "adapted from cube48opt-rust … with the author's permission" credits (search.rs:710-739 `reject_backward_coset`; the projection idea of search.rs:1261-1275).

Two independent readings of the notes were cross-checked against the code. The corner96 line is section F; the Opt8-11/H10 notes are spread through the tables.

Verdict codes:
- **HAVE**: we do the same.
- **BETTER**: we do more, with a measured gain.
- **GAP**: missing and applicable.
- **N/A**: missing, but it does not apply.
- **MEASURED-NO**: missing, measured, and it doesn't pay. The measurement is ours unless it says "theirs".

## Measurements

All counts: count.sh-style, 8 threads of one CCD, random:1000:2026 (h11 was not on the hugetlbfs mount during that phase of the comparison, so h8/h7). Lengths identical in every run (15:1 16:35 17:270 18:662 19:32).

### M1. Backward coset certificate (C9): MEASURED-NO

Implemented in lanes.rs (stream kernel) as `other_moves &= QUARTER_TURNS` when a moved-side child value (lookup or corner bound) is exactly `remaining + 1` of the node (child over by 2). Branch `neg/xcr-backward-coset` (on 1f5eb70; not retained in the published history).

| h8 | nodes/cube | lookups/cube |
|---|---:|---:|
| main 52ab88f | 22,986,834 | 19,752,820 |
| backward coset | 22,994,497 (+0.03%) | 19,758,988 (+0.03%) |

Why nothing: it is redundant. A later sibling gM′ has D_H(gM′) ≥ D_H(g) − 1 = its own remaining depth; with exact codes 1..3 its own table value already says so, and its `child_node` removes the same half turns (C3). Only code-0 (inexact) values can differ, at remaining ≤ base, where few nodes are. Theirs agrees: Opt10 nodes +0.13% (the −2.2% time was one unpaired pass), Opt8 WASM nodes −0.0086%, time +18.9%. Not timed (node counts decide).

### M2. Max over stabilizer frames (C14): MEASURED-NO

Upper bound of the gain: `Solver::index` takes, among all stabilizer frames of a self-symmetric corner class, the one with the largest table value, with every extra frame's value free. Branch `neg/xcr-projection-max` (not retained in the published history).

| | nodes/cube | lookups/cube |
|---|---:|---:|
| h8 main | 22,986,834 | 19,752,820 |
| h8 max over frames (free) | 22,753,385 (−1.02%) | 19,530,198 (−1.13%) |
| h7 main | 45,720,884 | 38,915,093 |
| h7 max over frames (free) | 44,505,601 (−2.66%) | 37,846,963 (−2.75%) |

A real implementation pays at least one extra probe (DRAM miss) and one more index computation per lookup of a self-symmetric class : measured 5.48% of index computations at h7 and 5.52% at h8 (sampled 1/1024, random:200:2026; a diagnostic counter on the same branch). That is more extra lookups than the at most 2.75% (h7) / 1.13% (h8) it could save, so net lookups rise by ≥ 2.7% / 4.4%. At h11 the gain is zero (exact table, all frames written by gen.rs). Theirs: Opt10 nodes −1.2%, time +3.7%.

## Benchmark facts

See the [cube48opt-rust benchmark setup](xcr-bench-entry.md). Points that affect running it fairly, all handled there:
- **18-thread cap** for one-cube search (`native_parallel.rs:13`).
- **4K pages** natively: tables in a malloc'd Vec, no madvise. Use the harness's hugeshim (thp or hugetlb mode).
- **Opt10 file format:** a 1 KiB header and minima ≤ 10, while cube48opt10's raw table stores 15 in unread minima. Handled by a loader-only shim on the comparison's cube48opt10 file; the bytes are proven identical to their official table by SHA-256.
- **No x86 prefetch in the official Opt10 feature set:** screen the `pf` build.
- **`CUBEOPT_SIMD=auto` picks AVX2:** AVX-512 is equal here.
- **Opt10 loads ~4 min per run.**
