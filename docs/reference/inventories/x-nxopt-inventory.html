nxopt technique inventory (agent x-nx)

Historical snapshot. Its source, timings and pending statements belong to the recorded experiment, not the current checkout. Documentation home.

Sources read in full: ~/ref/cube20src/nxopt.w (2062 lines), nxopt.md, makefile-nxopt, README.md, TODO.md, cubepos.w (move, inverse, movepc, symmetry, canonical sequences, threading), kocsymm.w, phase1prune.w, phase1prune2.w (the last three are the two-phase solver's, but they are in the same source set, so their techniques are listed too).

"Ours" cites main 55e048e (~/cube-opt); line numbers are of that commit. Every "have it" was checked in the code, not assumed. nxopt line numbers are nxopt.w unless another file is named.

Mapping used below (proved in the inventory notes at the end): nxopt's subgroup contains all U/D moves for the UD-axis table; H48's 48-symmetric subgroup H contains exactly the six half turns among the 18 moves. In our kernel a node branches on one side (the "moved" side a); the other side b is premultiplied by m^-1, so its value depends on the coset H m^-1 b.

Verdicts: done (we have it, or something strictly stronger), gap (applies, we lack it), n/a (does not apply to H48 / our setting), neg (tried, measured not to pay).

The 4-bit group minimum is the true minimum of its 62 entries and does not depend on the base. Re-basing only changes which exact values fall into code 0 and get replaced by max(min, cd), which for an 11 is usually 9-10. Free encoding idea (only with a regenerated table, tiny gain): effective base = max(base, group min), so groups with min >= 11 get exact 11/12/13 and >= 14.

M3, A8 tie-break by bounds (nxopt's rule, count*64 + bound): random:20000:99 nodes 3080725 -> 3080063 (-0.02%), lookups -0.02%. Neutral, as a2 found.

M4, 5.2 BPMX / pathmax. In-tree upward BPMX is complete. Every child value on either side, and the corner depth too, raises the node bound (note_value: lb = max(lb, v - 1), the face is dropped if v > r). Exhausted children return their learned bound (pop path). The node returns as soon as lb > r (top of advance), on both sides. Downward pathmax cannot prune in fixed-threshold IDA*, since the parent passed, so parent - 1 <= r - 1. It cannot restrict half turns either: that needs the side's own coset value. Job-level pathmax was the only open case, because jobs are extended whatever their parents' bounds. Measured with path bound = max over prefixes of (bound - distance): 0 jobs skippable on random:1000:2026, although 53 per cube drop by >= 2 on the inverse side.

Notes: why the mapping holds

  • Kernel conventions (simd.rs): a child moves a -> a m and b -> m^-1 b. The other side's value only depends on H m^-1 b (H contains the half turns): X2 keeps it, X and X' share it.
  • nxopt's skipval chains: a U move then a D move keeps the UD-axis probe on that end because both are in nxopt's subgroup. In H48 only half turns are in H, but X (face F) and Y (opposite face) commute, so Y^-1 X b = X Y^-1 b = X2 (X^-1 Y^-1 b): the same coset as Y^-1 X^-1 b. Two-move sequences on one axis therefore share the other side's value in 3 classes (quarter-quarter, quarter-half = the X child's own, half-quarter = the node's own Y child). Moves on other axes do not commute with X2, so nothing else is shared; and the moved side's cosets H a m share nothing.
  • A4 has no analog: a tight H48 probe forbids only the 6 half turns at its end; nothing forbids the quarter turns without probing the children.
