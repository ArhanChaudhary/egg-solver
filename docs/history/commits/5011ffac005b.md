## Original experiment record

m3: merged node counting in advance (negative, -1.1%)

advance counts the skipped X' moves and the generated move with one
popcount (reached = todo & (live ^ (live - 1))) instead of a separate
nodes += 1, and the exit test becomes lb > r || live == 0, with the
skipped moves of an exhausted node counted under a mask.

Why: one fewer add and one fewer branch per generated node.

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, interleaved, 3 runs,
solves/s):

| build          | run 1 | run 2 | run 3 | median |
|----------------|-------|-------|-------|--------|
| main b90b706   | 760.7 | 772.0 | 772.7 | 772.0  |
| merged count   | 728.9 | 763.5 | 763.9 | 763.5  |

Change: -1.1% (median). Hot-loop instructions per node (callgrind,
znver5 build without AVX-512, random:16:2026, 1 thread): 193.55 -> 196.06
(+1.3%). 1-thread solves/s: not recorded.

Conclusion: more instructions, not fewer. Likely the masked count of an
exhausted node's skipped moves and the live-based exit add work on the
pop path, and the pop branch then waits on the popcount chain.

Source: scratchpad m3/neg-merged-node-count.patch (= wip-cnt), made
against b90b706; applies cleanly. The same diff is also on
opt/neg-merged-node-count (7439b47).
Numbers are the agent's own (not re-measured for this record). Not merged; recorded per the rule that every candidate gets a branch.
