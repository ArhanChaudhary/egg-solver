Index-path micro-optimisations: cocsep LUT, vpmovmskb, lighter compose, cached table pointer

  • cocsep: CO_LO/CO_HI are pre-multiplied by N_CSEP (u32 tables), removing the imul from the cube -> cocsep load chain; bounds checks dropped.
  • edge_parts_sym: the S-slice mask uses inline-asm vpmovmskb. LLVM turns movemask(z+z) into vptestmb + kmovd, ~1.5 cycles longer on Zen 5, and this mask feeds the pext.
  • compose no longer ANDs with USED; bytes outside USED are left as garbage that never feeds back into used bytes (vpshufb indices in used lanes only address used lanes). equals/to_bytes mask instead. apply_move uses a precomputed MOVES_ORI orientation term (2-3 uops less per child).
  • Solver caches the raw table pointer (tptr) and has its own NTA prefetch and value(), so the table base stays in a register instead of two dependent loads per lookup.

Search is unchanged (depth18: 3607979 nodes/cube, lengths 18:100).
