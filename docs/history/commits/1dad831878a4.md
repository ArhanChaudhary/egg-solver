Applies on top of p18 (commit 71eadca on main 55e048e: 18-bit packed cocsep entries, corner depth by class: +1.59%
median at 1T layout-averaged on 55e048e), two variants that shorten its
index chain, both worse than p18:

- p18b: rows of 70 tetrad separations padded to 72 entries (162 bytes per
  corner-orientation row, 354 KB instead of 336 KB), so that an entry's
  byte offset in its row and its bit shift come from the tetrad mask
  alone (two small parallel table loads): no `shr`/`and` on the chain.
- p18c: p18b, with the entry read from the byte before it and shifted 3
  bits less, so that `v & 0x1F8` is the symmetry index times 8, a scaled
  index of the 64-byte `sym_edge` rows: no `shl`. Its index path is 1 µop
  above main's.

The index paths are as intended, but register allocation in the stream
loop gets worse elsewhere (p18b: the table base is rematerialized 4 times
in the index path; p18c: 25 `lea` of the table base in the loop vs 17 in
p18).
