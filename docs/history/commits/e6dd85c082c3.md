## Original experiment record

b2: node stores the chosen-side cubes, 96-byte node (negative, -2.9%)

Node keeps its cubes by role instead of by side: a (the cube moved on the
chosen side), b (the other side's cube), lo (the other side's bound) and
mm_o (the other side's move mask) replace c/ci/ln/li/mm_n/mm_i. advance
then needs no side select per child; the select moves to make_node (once
per push). The node shrinks from 128 to 96 bytes (static assert added).

Why: remove the per-child select on node.normal from the hot path.

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, interleaved, 3 runs,
solves/s; skipk2 = skip-sibling, the same tree as b90b706):

| build             | run 1 | run 2 | run 3 | median |
|-------------------|-------|-------|-------|--------|
| main fe58740      | 680.1 | 683.5 | 684.3 | 683.5  |
| skipk2 (b90b706)  | 763.4 | 771.3 | 780.2 | 771.3  |
| skipk3 (+ this)   | 748.7 | 740.3 | 770.0 | 748.7  |

Change: -2.9% (median); per run -1.9, -4.0, -1.3%. A second session
(main 671.3 / 684.8 / 680.7) had skipk3 at 704.9 / 767.8 / 759.5, with no
skipk2 in that run. 1-thread solves/s: not recorded.

Conclusion: slower. m4 later made the same role layout (node-roles,
496b096, merged in 35c608c) but kept the node at 128 bytes with
#[repr(align(64))], and it gained +0.5%. So the loss here most likely
comes from the 96-byte size, not from the layout. The mechanism was not
identified; candidates are the sp * 96 address arithmetic and nodes no
longer aligned to cache lines, so a node and its neighbour share a line.
