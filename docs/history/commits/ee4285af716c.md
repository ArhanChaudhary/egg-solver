## Original experiment record

b2: unified resolve on top of skip-sibling (negative, -4.5%)

The unified-resolve change (one resolve for both lookup kinds, with the
pending kind as data, and no match on the phase; see
neg/b2-unified-resolve) applied to the skip-sibling WIP (skipk, the
previous commit).

Why: after skip-sibling removed most per-child mispredicts, the phase
dispatch was the largest remaining one in the TAGE simulation (0.285 per
node on main).

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, solves/s, 1 run):

| build                      | solves/s | change     |
|----------------------------|----------|------------|
| main fe58740               | 662.8    |            |
| skipk (previous commit)    | 764.0    |            |
| skipku (+ unified resolve) | 729.9    | -4.5% vs skipk |

1-thread solves/s: not recorded.

Conclusion: slower, as on main (-3.3% and -3.8%). Real Zen 5 hardware
predicts the phase dispatch much better than the simulator, so removing
it only adds blends and work. Later rounds kept the dispatch and made it
cheaper (m3: pending value loaded before the dispatch; m4: phase
encoding).

Source: scratchpad b2/neg-skipk-unified-resolve.patch (= wip-skipku,
cumulative on fe58740). Recorded as two commits on fe58740: skipk (the
previous commit), then this increment; the branch's tree equals
fe58740 + the patch.
Numbers are the agent's own (not re-measured for this record). Not merged; recorded per the rule that every candidate gets a branch.
