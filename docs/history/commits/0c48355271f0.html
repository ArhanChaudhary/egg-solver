Sibling-face pruning and back-jumps from learned child bounds

Every lookup value (normal or inverse, corner bound included) is a lower bound on the true distance, which changes by at most one per move. So:

  • a child value v >= r1+2 prunes the same-face siblings (one move apart), without recursing into them (cube48opt's sibling-face pruning, extended to use all values known for the face and values learned from subtrees);
  • v - 1 bounds the node itself: if it exceeds the remaining depth the node is abandoned (back-jump), and dfs returns the learned bound so that the parent can prune further.

Also: bench prints per-solve timing and a steady-state throughput (threads / mean per-solve time), which avoids the end-of-batch tail (with 1000 cubes, ~30% of thread time was idle waiting on the last long solves, making batch wall-clock numbers depend on where long solves land). bench.sh now reports the median steady-state throughput as the primary metric.
