NEGATIVE m8: Worker::rounds keeps only the lane pointers live (neutral to negative)

The pointer walk of 95cbb11 raised Worker::rounds' stack operands from 102 to 124 (static count). This variant keeps only next and end live across the visits: the vector's base (for offset_from after on_end) and the active count (for the per-round counters and maintain's test) are read from self again where needed.

asm: rounds 1231 -> 1229 instructions, stack operands 124 -> 119. A perf cpu-clock profile of the loop (share 1T) puts ~2% of its samples on instructions with stack operands: the spills are mostly the solver's loop-invariant fields (packed and table pointers, base, max value, row multiplier, eo mask) hoisted out of the loop and reloaded, which cost the same as loads from the solver; not the pointer walk's.
