## Original experiment record

lanes, share, solver, bins, wasm: give up past 20 moves instead of asserting; no panics

The user asked that the code have no intentional panicking paths.

* The search target is at most solver::MAX_TARGET = 20 (God's number):
  Lane::start_iteration returns false instead of assert!(target < MAXD)
  and the lane reports the cube with no solution (Step::Unsolved,
  Start::Unsolved); share's settle gives the cube up (give_up) instead of
  building past it, the first pass never jumps above it, and build clamps
  the target (it lowers only a first bound above 20, whose iteration finds
  nothing). const _: () = assert!(MAX_TARGET < MAXD) keeps the stacks'
  unchecked indices in range whatever the table says. Only an unsolvable
  cube or a table whose bounds are too high gets there (it used to panic).
  Solver::solve stops there too.
* done callbacks (run_lanes, share::Done, solve_all, Pool::run) and
  Solver::solve report Option<Vec<u8>>: None = no solution within 20
  moves. bench counts it as a bad solution (now an error, not an
  assert_eq!), solve prints BAD (or "no solution within 20 moves"), wasm
  returns an error object.
* share: capacity asserts -> reserve() after clear() (a no-op: the buffers
  are pre-sized); the parallel extension's assert_eq! -> debug_assert_eq!
  with the proof, and the copy reads at most the jobs there are;
  unwrap()s of joined slots -> let-else (always joined), fresh joins with
  add_local (it holds the cube's part already) instead of local().unwrap();
  split's unreachable!() -> no split; solve_all reports thread start and
  join errors.
* bench, solve: thread start failures stop the others and return an
  error, joins are checked, poisoned mutexes are used as they are;
  random_scramble uses Rng::below_usize. portable to_bytes without
  copy_from_slice.
