NEGATIVE x-vc: clflushopt-table-lines (not merged)

From 472a49def33a7bc49f50945211ca5e4f01b84588 Mon Sep 17 00:00:00 2001 From: Ubuntu super@claude-cube.usubflgyqkfexnnpr2q2liw1rb.bx.internal.cloudapp.net Date: Wed, 4 Nov 2026 10:14:36 +0000 Subject: [PATCH] NEGATIVE (x-vc): evict each resolved lookup's table line with CLFLUSHOPT MIME-Version: 1.0 Content-Type: text/plain; charset=UTF-8 Content-Transfer-Encoding: 8bit

A model of the L2 (LRU, 1 MB 16-way, one uniformly random cocsep entry per index plus 0.85 never-reused table lines per index; sim in /data/agents/x-vc/sim/l2sim.c) reproduces the measured footprint sensitivity only if the NTA-prefetched table lines occupy L2 like normal lines: cocsep L2 hit rate 80% at 3-byte entries, 67% at 4-byte (measured -1.6%), 90% at 18-bit (measured +1.6%). If the dead table lines left L2, the model gives ~100% cocsep hits. So this experiment flushes the line of the lookup just resolved (CLFLUSHOPT, inline asm) at the three sites that issue a lane's next lookup (advance, resolve_other, push_advance), one µop each.

Search unchanged.

1 thread (bench stream 10 60 1 24, solves/s, paired with main 55e048e, layout none): main 23.867, flush 16.633 (-30.3%). Stopped after one pair: CLFLUSHOPT is far too expensive on Zen 5 to spend per lookup.
