Original experiment record

lanes: 24 lanes per thread by default

Each lane keeps one table miss in flight, and a round of visits is the slack each miss gets. The kernel is now fast enough that 20 lanes leave misses exposed: at 1 thread, per-visit instruction cuts of up to 5.7% measure as 0, while 16 / 28 lanes move throughput by -9.6% / +10.2%. 24 is the best at 48 threads and within 0.4% of the best at 1 thread, so it becomes the default for every thread count (lanes::DEFAULT_LANES, used by bench and solve; bench.sh's default too). Benchmarks that pass the lane count explicitly are unaffected. A per-thread-count rule is not worth it: the 1T optimum (28-32) beats 24 by only 0.4%.

The search is unchanged (the lane count does not affect a cube's search).
