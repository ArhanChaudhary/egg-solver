Subject: [PATCH] neg: base 11 for the h11 table (emulated exactly from the
 base-10 table)

nissy-core and cube48opt use base 10 for h11 (codes: <=10 with a
fallback, 11, 12, >=13). This count-only experiment emulates a base-11 h11
table exactly with our base-10 one (env CUBE_BASE11=1):
- true 11 (code 1) falls back like code 0 (group minimum, corner depth);
- code 2 stays 12;
- code 3 is 13 if one of the 18 neighbors has code 2 (exactly 12), else
  >= 14 (a coset outside the subgroup is 1 + its nearest neighbor away).

random:1000:2026, 8 threads of one CCD (count.sh style); lengths identical
(15:1 16:35 17:270 18:662 19:32):

| table          | nodes/cube | lookups/cube |
|----------------|-----------:|-------------:|
| base 10 (main) |    3058198 |      2588380 |
| base 11        |    3368592 |      2960401 |
| change         |     +10.2% |       +14.4% |

Negative: losing the exact 11 costs more at r1 = 10 (0.33M lookups/cube)
than the new 14 saves at r1 = 13 (63K lookups/cube). Base 10 stays.
(Base 9 or merged levels would lose an exact level at r1 = 11..12, where
most lookups are.)
