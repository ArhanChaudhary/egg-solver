tables::file, cubie: with_capacity at known sizes

The common "Vec/String::with_capacity when the final size is known" idiom, at the two library sites that grow to a size known up front. The cocsep per-class tables are preallocated by the previous commit.

  • Trailer::to_bytes: String::with_capacity(TRAILER_BYTES): one 4096-byte allocation. Before, String::from(MAGIC) reallocated as the lines were written, and the resize to 4096 bytes reallocated again.
  • cubie::symmetries(): Vec::with_capacity(48) for the 48 signed permutation matrices (was an allocation of 4 and reallocations up to 64). Both run once per process (or per written table).

Hot code untouched (vs the previous commit, same folder, main ca820b6): bench and solve .text and .rodata are byte-identical (objcopy + md5). Neither function is linked into them; only the panic-location line numbers in .data.rel.ro move. In gen, write_trailer changes at the same size.
