Merge opt/l6-share-a: share-mode hang fix, parallel staged builds (-39% latency)

Two share.rs commits:

  1. count down a lane's ended jobs when it takes a piece. This fixes a latent hang: a lane that took a donated piece never counted down its finished claim, so the iteration never ended. New test share_stress (16 threads x 1 lane) hangs on 78ce33e.
  2. builds in stages use all threads, and no fresh pages. A cube was dropped from the open list between stages, so the staged sort ran on one thread. Build buffers are pooled, so there are no page faults. Infeasible jobs are sorted last and not claimed.
