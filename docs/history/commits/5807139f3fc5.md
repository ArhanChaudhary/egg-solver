NOT FOR MERGE (superseded), but not a negative. Against 595e424.

advance counted the generated and the skipped nodes in a local `nodes`
and added it to `stats.nodes` on return. LLVM keeps the local in a
register, spills it across the index computation and reloads it at the
return. Here every site adds to `stats.nodes` directly (the skipped X'
moves at the exhausted-node exit, skipped + 1 at each generated child),
so no counter is live across the loop. The search is identical.

Instructions per node (cachegrind, x86-64-v3 build, random:20:2026, 1T,
on cb8cb70): 148.79 -> 145.73 (-2.1%).

At one code layout (cb8cb70, 20 lanes) this measured -0.7% at 1T (5
paired runs: main 21.633, memcnt 21.483), and was filed as a negative.
Layout-averaged on 595e424 (abl1t.sh 2: 4 lld shuffle layouts x 2
paired runs, 24 lanes), it is positive:
