## Original experiment record

tables: map table files opened for solving read-only

`Mem::file` opened and mapped every table file read-write and shared,
also when only solving with it (`H48Table::open` on hugetlbfs or
/dev/shm). A stray write through the table pointer (a bug elsewhere)
would then silently corrupt the shared 58 GiB table for every process,
and the corruption would persist. Now the file is opened read-only and
mapped `PROT_READ` unless it is being created (table generation): such
a write faults instead.

Test `opened_table_file_is_read_only`: a table on /dev/shm is mapped
`r--s` (/proc/self/maps).

The pages and their huge-page mapping are the same; paired 1-thread
stream runs of the whole stack against its base are in the cover note.
