cubie, build.rs: format_moves writes one String

The common "write into one String instead of format! temporaries and collect + join" idiom (clippy's format_collect / needless_collect family):

  • cubie::format_moves (solve's and the wasm module's output line, once per cube): one String::with_capacity(3n). The new push_move_name appends each name. Before, there was one String per move (format!), a Vec and a join. move_name shares push_move_name.
  • build.rs list(): write! into one String instead of a Vec and a join. The generated consts.rs is byte-identical (md5).

Allocations per cube in solve (pb1's counting allocator, previous commit -> this one): solve -t 2 -c 1 random_state 100: 25.2 -> 6.5; random_move_15f 300: 21.4 -> 5.5.

Hot code untouched (vs the previous commit, same folder, main ca820b6): bench is byte-identical (.text, .rodata, .data.rel.ro: format_moves is not in it). In solve, the per-cube output callback solve::main::{closure#4} goes from 2145 to 1474 bytes, plus push_move_name (216 bytes): .text -448. The pinned share code (rounds at 0x310, the thread entry, run_pinned) is instruction-identical at the same page offsets.

Not kept: the same idiom in share's Pool::counters (end-of-run summary). LLVM unrolls the 14 write! calls there: bench::run +1,020 bytes (neg/g1-counters-write).
