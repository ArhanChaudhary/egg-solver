lanes: round-robin without a per-round exit branch

NEGATIVE. Against 0a71855 (the round-6 stack on 78ce33e through "resolve", i.e. m6-6).

The lane loop for l in lanes[..nactive] inside while !stop exits once per round, and that exit is mispredicted at nearly every round end. This patch wraps the visits around with a select (add, cmp, cmov) and tests stop when a lane solves a cube. TAGE trace: 0.7371 -> 0.6952 mispredicts per node (the loop branch, 0.044, is gone); cachegrind (v3) 148.79 -> 147.52 instructions per node. Search identical (verify OK), check.sh OK, share mode lengths unchanged.

But it is slower: the next visit's first load (k_idx) now waits for the cmov chain (cmp against the spilled end pointer, cmov from the spilled base: two stack loads), whereas the predicted branch let the front end run ahead into the next lane at once. The loss outweighs one ~15-cycle mispredict per 20 visits. Computing the next pointer at the top of the visit (ring2) only gets back to neutral: LLVM spills it and reloads it at the end.
