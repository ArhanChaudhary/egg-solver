lanes: fewer µops per child (lazy child cube, early stores, blsmsk count, move tables, index tweaks)

NEUTRAL (not proposed as a whole). Against cb8cb70 (= fc6d9c9's tree). Search unchanged (verify.sh: 3295521 / 2785769, 15:1 16:35 17:270 18:662 19:32; 3607979 / 3053364, 18:100).

Seven per-visit instruction cuts, each with a clear mechanism, none of which moves throughput.

  • early: the pending child's k_face, k_po, phase and the node count are written before the index computation, so they are not live across it. This removes the spill/reload of the local node counter (a child pruned by its corner depth reads the fields back, volatile).
  • cnt: the reached moves are counted with blsmsk (todo & (live ^ (live - 1)), all of todo if live is 0): one popcount covers the skipped X' moves and the generated child. This is fewer instructions than the bzhi form, unlike neg/m3-merged-node-count, which added a masked count on the pop path.
  • kind: face, kind and face mask of a move come from TABS tables (no imul/shr/lea/sub).
  • kind2: the X-move blend mask is a k-register loaded from a table (Cube::select_mask), not sbb + kmovd.
  • idx: Tinv's eo is folded into the first xor of edge_parts_sym, which becomes a vpternlog with a memory operand: no load of p as a register, no z ^ p. sym_edge entries are 128 bytes (q, p, eo), so the entry offset stays one masked, scaled index. msplit's pext is 64-bit, with a 64-bit vpmovmskb output (no zero extensions).
  • lazy: advance computes only the looked-up child cube, as one composition of operands selected by the table mask (Cube::child_lookup: inv_mv[m] o b for X moves, a o mv[m] else). The other cube is computed on the pass and push paths only. This is a new angle on neg/m6-lazy-child-cube, whose mask came from m % 3 at the head of the index chain.

Instructions per node (cachegrind, x86-64-v3 build, random:20:2026, 1T): main 148.79; early 146.86; early+cnt 144.50; the whole stack 140.25 (-5.7%; on v3 the k-mask blends fall back to vpblendvb, so the native cut is larger). kind alone was +2.0 (face spilled twice), and idx2 alone 148.07.

Why: at 20 lanes the 1T kernel is bound by memory-level parallelism (see the lane patch). But at 28 lanes, where more lanes no longer help, the stack is still flat. Visit time is set by the mispredicted branches and the latency of their inputs, not by µop count: 9 extra cycles on the value chain cost 1.7% (diagnostic), while 3 extra instructions off the chain cost 1.0% and 8.5 fewer cost nothing.
