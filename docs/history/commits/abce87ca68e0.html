lanes: code for root children without statistics, rest phase by the job's best code (c8)

Two changes to c7's child ordering in the split iterations, both outside the search loop (end of a run, and the build of an iteration's rest):

  • A run's root child whose statistic is 0 gets code UNSEEN_CODE = 48 (plus the face step) instead of 0. Statistic 0 means no lookup was resolved in its subtree in the previous iteration: X pruned by its other side (13 at T = 17), its X' with it, or a half turn left out by a tight root. They are ~48% of the last iteration's nodes, and per node they lead to a solution about as often as children with codes near 48 (bounds 12/12 or 13/12 with nothing below; measured on 1000 cubes with c8's dataset of the last iteration). With code 0 they never were candidates and their jobs' rest runs came last.
  • The rest phase ranks a job by its best code over all its children, including those already run in this iteration's first part (whose codes then are of this iteration), instead of only the children left: a job whose best child ran without a solution is still more promising than one whose best child is weaker.

Each alone is about -0.5% nodes; together -1.0% on the large sets. The neighbours are flat on random:20000:99 (UNSEEN_CODE 44 / 56: +0.03 / +0.07%; FIRST 0.15 / 0.25: -0.01 / +0.09%; MERGE 3 / 6: -0.02 / +0.07%). Tuning note: the per-cube cost is heavy-tailed, so over 1000 cubes the standard error of a change in nodes/cube is 0.6-1.4% of the total for changes of this kind (+-1.1% here); the 20000- and 33468-cube sets decide (c8's simulator of this machinery replays the counts exactly; negative study and tools: c8/neg-predictor-study.patch).
