## Original experiment record

m4: paired lookups for X children (negative, -40%)

An X child issues its other-side and moved-side lookups together (k_idx
and k_idx2), and the lane waits in a single Wait phase with one resolve
per child: no WaitOther/WaitMoved dispatch. Search unchanged.

Why: one visit per X child instead of two, and no phase dispatch (the
largest mispredict site in the TAGE trace, 0.367 per node).

48 threads (bench /mnt/huge/h11 stream 20 30 48 20, capped, interleaved,
2 runs, solves/s):

| build              | run 1 | run 2 | mean  |
|--------------------|-------|-------|-------|
| main ff2b7a4       | 836.3 | 819.0 | 827.7 |
| paired lookups     | 491.1 | 489.9 | 490.5 |
| (diag: + 1 index)  | 719.8 | 718.8 | 719.3 |

Change: -41.3, -40.2% per run (about -40%). 1-thread solves/s: not
recorded.

Conclusion: far slower. The other side passes for only a minority of X
children (b2 measured ~17%), so pairing almost doubles the index
computations and DRAM fetches. One extra index per node alone costs 13%,
and with its prefetch 17% (neg/m4-diag-extra-index*). The saved dispatch
cannot pay for that.

Source: scratchpad m4/neg-pair-lookups.patch (= wip-pair1), made against
ff2b7a4; applies cleanly.
