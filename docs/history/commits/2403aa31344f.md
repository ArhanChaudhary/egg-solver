## Original experiment record

gen, solve, bench: check disk and memory before the run, not deep into it

User request: "Do this for the program itself instead of failing when its
deep into a run". The programs now check before any work that what they
will need is there, and stop at once with exit status 2 and the numbers:

  gen: /data2/tables has 18.2 GiB free, h11 needs 58.0 GiB (+ 0.6 GiB
  margin); free space, or choose another OUT or a smaller k (--force
  skips this check)

* gen generate (also --parts and --dfs) and gen derive:
  - room for each table file (exact: h48_bytes(k) and the 4 KiB trailer;
    files on one file system together, e.g. h11 and its k:base:path
    extras): free space by statvfs (plus what an existing file at that
    path frees), 1% + 64 MiB margin; on hugetlbfs (statfs f_type) the free
    pages of the mount's page size less the reserved ones
    (/sys/kernel/mm/hugepages/hugepages-<size>kB), within the mount's
    quota if it has one, for the file in whole 1 GiB pages;
  - memory (MemAvailable, and no more than the cgroup v2 memory.max
    limits leave: a run over them is killed, e.g. under systemd-run -p
    MemoryMax=; 256 MiB margin): BFS the table unless it is built
    in place on hugetlbfs, and each derived table not on hugetlbfs
    (written through mappings; /dev/shm counts as memory); depth-first one
    part (--parts N: 1/N); derive the new table; and the generator's own
    0.3 GB;
  - a missing output folder (which BFS found only when it wrote the table,
    at the end);
  - --force skips the checks. gen stamp writes inside the file (it never
    grows it) and reads the table through a mapping: nothing to check.
* solve, bench, cubeopt: before copying a table into memory (--load copy,
  or auto off hugetlbfs and /dev/shm on Linux), the memory must hold it
  ("use a copy on hugetlbfs (mapped, not copied: --load map) or a smaller
  table"). Mapped loads (h11 on /mnt/huge) do no check and nothing more.
* -v logs each check (place, free, needed, margin).

The logic is cubeopt::cli::preflight: check(needed, margin, available), a
pure function with unit tests, and the measurements (room, memory_available,
files, memory). statvfs on unix, hugetlbfs/tmpfs and /proc/meminfo on
Linux; elsewhere (wasm) nothing is measured. CUBEOPT_PREFLIGHT_LIMIT (bytes,
undocumented, for tests) caps every measured amount: tests/cli.rs
preflight_failures makes gen generate/derive and solve --load copy fail on
h0 (exit 2, nothing written), --force pass, and a missing folder fail.

Checks: check.sh with /data/tools/bin on PATH (bun) passes. objdump vs
0b5b5a6: bench::stream_thread, Worker::rounds (bench and solve),
share_thread, bench's run thread closure, solve's pinned thread closure
and share::deeper instruction-identical, frames the same (0xfc0, 0x98,
0xfc0, 0x700, 0x1000, 0x190); solve's rounds at page offset 0x310 as
main; bench's unpinned stream_thread moves 0xa90 -> 0xf10. Search
identity: verify.sh cannot run now (/mnt/huge/h11 is removed for the
final comparison's memory steps, and 6 GiB available cannot hold a copy);
instead, on /mnt/huge/h8 at 8 threads, main and this give the same
counts: random:200:2026 nodes/cube 24764016 lookups/cube 21265828,
lengths 16:8 17:34 18:151 19:7; depth17 x50 4120993 / 3542529, 17:50.
