Original experiment record

NEGATIVE: BOLT post-link layout (build-bolt.sh): +0.3% at 1T on cb8cb70, within noise

build-bolt.sh steps:

  • Relink the release build with --emit-relocs and instrument it with llvm-bolt -instrument. There is no PMU here, so no LBR sampling.
  • Train on the real table:
    • bench: a 1-thread stream (3+20 s) and a 2-thread share batch (100 random cubes, seed 99);
    • solve: a 2-thread batch of 100 scrambles. The counters are shared, so the instrumented 1T stream runs at 12.1 solves/s (vs 20.5), the 2-thread share batch at 5.8/s, and an 8-thread share batch did not finish in 4 min.
  • Run llvm-bolt -reorder-blocks=ext-tsp -reorder-functions=hfsort -split-functions -split-all-cold -split-eh -icf=all. Total about 1.5 min; uses llvm-bolt 20.1.2 (apt bolt-20, installed). README.md has a short note.

The search is unchanged. verify.sh prints the reference nodes, lookups and lengths (78ce33e build). The BOLT solve gives the same length for all 500 cubes of random_state.txt; per-cube nodes vary run to run in share mode, for main as well. check.sh OK.

dyno-stats: -63..-70% taken branches, -1.7% instructions. 97.4% of the 1T samples are in the one stream closure (31.4 KB). BOLT splits it into 24.9 KB hot and 6.4 KB cold, so function order does not matter.

On 78ce33e the hfsort layout looked like a win: +0.7..1.2% at 1T over 12 paired runs. But that was where the hot loop landed, not the layout:

  • the identical code with cdsort order starts 22 bytes further into its 64-byte line and gains only +0.2..0.3%;
  • 64-byte function alignment alone (llvm-args negative) costs main 0.8%. On cb8cb70 (the m6 micro stack) the same pipeline gives +0.3% (hfsort) and +0.2% (cdsort), both inside the ±0.5% 1T noise. So no 48T confirmation was run (48T lock budget); the earlier 48T runs on 78ce33e showed nothing either. Not worth a build step.

Binaries:

  • on 78ce33e: boltH = the script's output; bolt-ss = the same pipeline from another training run (identical hot code at the identical address); boltA = cdsort; bolt1 = stream-only profile; bolt2 = no splitting; bolt3 = + -align-blocks; bolt-nl = profile from cpu-clock perf sampling, perf2bolt -nl (no LBR);
  • on cb8cb70: fc-bolt = the script's output; fc-bolt-cd = cdsort.
