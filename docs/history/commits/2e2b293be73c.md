## Original experiment record

b2: branch-free skip guard and a single pop branch (negative, -8.1%)

In advance, the skipped-X' counting runs unconditionally (masked by
open = lb <= r) instead of under an `if node.lb <= node.r`, and the two
exits (node pruned by its bound, no move left) become one branch on
`!open | (live == 0)`. Measured as skipk7 on top of skipk6 (skip-sibling
+ cached cocsep pointer + merged node counting, the previous commit).

Why: remove the lb <= r branch and leave a single pop branch per visit.

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, solves/s, 1 run):

| build                       | solves/s | change      |
|-----------------------------|----------|-------------|
| main fe58740                | 679.3    |             |
| skipk6 (previous commit)    | 773.8    |             |
| skipk7 (+ this)             | 711.5    | -8.1% vs skipk6 |

1-thread solves/s: not recorded. Instructions per node: not measured for
skipk7 (skipk6: 203.5).

Conclusion: much slower, well beyond the +-3% build noise b2 saw. The
agent did not pin down the cause. Likely: the merged exit test needs both
lb and the post-skip todo, so the pop branch resolves later and its
mispredicts (about 0.13-0.15 per node) cost more; m4 later measured that
a mispredict which waits on the looked-up value costs about 30% more than
one resolving from registers.

previous commit), then this increment; the branch's tree equals
fe58740 + the patch. The cumulative diff is also on
