Merge opt/r7-series: share race fix, table hardening, Miri, stress tools

Correctness series from the review/stress agent. None of it is intended to change performance.

  1. share: join a fresh cube before publishing it. Worker::fresh joined its new cube only after build() had published it. In between, another thread could claim, solve and release the cube, so local() returned None and the unwrap panicked (abort in release builds). Reproduced on cb8cb70 (30 panics + 14 hangs in 100 mock-search runs) and on the l6 build (4/20 heavy stress runs). The deterministic test share_fresh_cube_solved_by_others_at_once fails 5/5 without the fix and passes 100/100 with it.
  2. miri: cfg(miri) intrinsic equivalents for the 3 inline-asm sites (normal builds unchanged; disassembly identical up to addresses), a Miri-compatible Mem::anon, and miri.sh (cubie, simd, coord, hot index path, sorts, share protocol). No UB found.
  3. tests and tools: hot_index_matches_reference_index and conjugates_have_equal_lengths_in_all_modes in check.sh; the examples/xsolve cross-check driver (independent plain IDA* reference mode), examples/tabcheck and stress.sh.
  4. tables: read_meta rejects k > 11 or base > 12, and open checks the file size against k. A bad base broke an assert_unchecked in resolve_moved (UB), and a stale meta file gave inadmissible bounds, i.e. silently non-optimal solutions.
  5. tables: map table files opened for solving read-only.

Stress coverage, all solutions verified, 0 length mismatches:

  • 48T, -c 7, 3 lanes;
  • vcube cross-check on 400 cubes;
  • cube20.org's 100 distance-20 positions, all 20;
  • tabcheck of 4e9 h11 entries;
  • TSan on all share tests: clean.
