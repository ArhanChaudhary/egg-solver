bench: each mode's thread code compiled on its own

bench's thread closure ran either the share mode (Pool::run) or the stream loop (run_lanes), and LLVM inlined both into it, so the stream loop's register allocation and stack frame depended on share.rs. For example, the stream code of bench at main differs from that of c7 without l6-share-2, although lanes.rs is the same.

Each mode now runs in a function of its own that is not inlined: share_thread and stream_thread. stream_thread is byte-identical (addresses aside) whether it is built on main or on c7 without l6-share-2, so changes to share.rs no longer change the stream code. Its placement in the binary still moves with any change, as every function's does. solve has no stream mode, and its binary is byte-identical to main's. examples/xsolve.rs still runs both modes from one closure.

A first version also made Pool::run #[inline(never)]. That moved solve's rounds from 16 to 48 mod 64, and solve -c 0 at 1 thread lost 1.5% (a layout effect: with all functions aligned to 64 bytes, the difference was 0.2%). The share mode is left as it was.

Measured on main f2cb1f4, h11 table, random_state = cube_solver_test dataset/random_state.txt (500 cubes), every binary built in the same folder. 48 threads: paired, i.e. 5 exclusive holds, each running every binary back to back after the quiet gate (outside load 0.0-0.5 cores); bench share and stream with 24 lanes (the default). 1 thread: the binaries of a run ran at once in L3 slots, launch order rotated.
