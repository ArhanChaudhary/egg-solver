## Original experiment record

b2: branchless moved-side resolution (negative, -2.2%)

resolve_moved always writes the pending child into the stack and does
sp += push (0 or 1) instead of branching on whether the moved side's
value prunes the child. Incremental on the skip-sibling patch (7a173a1,
merged as b90b706).

Why: per-node cost on Zen 5 was dominated by mispredicts (~22 cycles
each), and the TAGE simulation of main put the moved-side prune at 0.114
mispredicts/node.

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, interleaved, 3 runs,
solves/s; skipk2 is skip-sibling with the same tree as b90b706, skipk9 is
skipk2 + this change):

| build             | run 1 | run 2 | run 3 | median |
|-------------------|-------|-------|-------|--------|
| main fe58740      | 677.3 | 680.0 | 669.4 | 677.3  |
| skipk2 (b90b706)  | 774.1 | 767.1 | 776.5 | 774.1  |
| skipk9 (+ this)   | 752.9 | 758.8 | 756.7 | 756.7  |

Change: -2.2% (median).

Instructions per node (cachegrind, x86-64-v3 build, random:16:2026,
1 thread): 202.4 (skipk2) -> 212.2 (skipk9), +4.8%.
1-thread solves/s: not recorded.

Conclusion: slower. The unconditional 128-byte child write and the sp
arithmetic add about 10 instructions per node, and the agent's TAGE
simulation showed the pop branch's mispredicts rising: the removed branch
carried history that helped predict it. (b2 notes that variants of this
code swing by about +-3% between builds; this one is consistently
negative in all three runs.)

Source: scratchpad b2/neg-moved-push-branchless-incr.patch, made against
b90b706; applies cleanly. The same diff is also on
opt/neg-moved-push-branchless (cfe7854).
Numbers are the agent's own (not re-measured for this record). Not merged; recorded per the rule that every candidate gets a branch.
