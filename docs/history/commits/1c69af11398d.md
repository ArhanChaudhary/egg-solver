## Original experiment record

m4: Node::lb replaced by a max-fmax byte and a dead mask (negative, -1.1%)

Node::lb is replaced by fmx = max(fmax) (no saturating_sub per update),
and face_keep() also clears the whole todo once a face's bound exceeds
r + 1 ("dead"), so advance needs no separate lb > r test per step.

Why: one fewer compare-and-branch per advance step.

48 threads (bench /mnt/huge/h11 stream 20 30 48 20, capped, interleaved,
3 runs, solves/s; measured as c7 = c6 + this change, against c6, the m4
WIP stack after six steps):

| build          | run 1 | run 2 | run 3 | median |
|----------------|-------|-------|-------|--------|
| main ff2b7a4   | 842.8 | 832.5 | 829.3 | 832.5  |
| c6             | 887.7 | 887.3 | 886.9 | 887.3  |
| c7 = c6 + fmx  | 877.7 | 864.2 | 881.5 | 877.7  |

Change: -1.1% vs c6 (median); per run -1.1, -2.6, -0.6%.
1-thread solves/s: not recorded.

Conclusion: slower. Likely the lb > r test was predictable and cheap,
while the dead-mask computation adds work to every noted value.

Source: scratchpad m4/neg-fmx.patch (mk-nolb3.py applied to ff2b7a4),
made against ff2b7a4; applies cleanly. (It was measured on top of c6.)
Numbers are the agent's own (not re-measured for this record). Not merged; recorded per the rule that every candidate gets a branch.
