Idea 7.4 (ranking with a table per half) applied to the cocsep offset of
the index path. The tetrad-separation rank is colex, a sum over the set
positions; with 4 bits set in all, the low half's popcount is 4 minus
the high half's, so the rank splits additively over the halves of the
8-bit mask. One pext of the corner bytes (tetrad bit and the 2
orientation bits of each corner) then gives two keys, and

  3 * cocsep = lo[key & 0xFFF] + hi[key >> 12]

(`lo`: corners 0..3, 4096 x u16; `hi`: corners 4..7, 1024 x u32). That is
1 pext, 2 loads and 1 add instead of 2 pexts, 3 loads and 2 adds:
index 45 -> 43 Ir (callgrind, x86-64-v3 op microbenchmark), microbench
throughput 2.75 -> ~2.6 ns per index. The cost is ~10.5 KB more of
lookup tables (12 KB instead of 1.5 KB), all of which is hot in L1:
the keys are uniform over the 1296 valid `lo` entries.
