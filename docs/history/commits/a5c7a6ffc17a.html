lanes: one allocation per solution in Lane::reconstruct

The common "with_capacity + extend instead of to_vec + push and a temporary Vec" idiom, on the per-solution path of both modes. reconstruct allocates the solution once, at its final length (job moves + path + pending move). It reads the inverse-side moves from the stack in reverse, instead of collecting them in a second Vec and growing the result by push.

Allocations per cube (pb1's counting global allocator, diag/alloc-count, on 0d1a0e8: before -> after, allocations + reallocations):

  • bench stream 1T: 10.2 + 3.6 -> 9.7 + 0.6;
  • bench share 1T, random:300: 5.7 + 3.0 -> 5.3 + 0.0;
  • solve -t 2 -c 1, random_state 100: 25.7 + 3.1 -> 25.2 + 0.1.

Hot code untouched (vs the previous commit, same folder, main ca820b6): reconstruct is out of line (called from the found paths) and goes from 694 to 605 bytes. It is the only changed function. stream_thread, Worker::rounds, share_thread and the thread entries (bench and solve's pinned share code) are instruction-identical, with the same line offsets and frames. .text: bench -96, solve -96. In bench, the hot loops move by -0x40 within their page (stream_thread 0x5d0 -> 0x590, rounds 0x190 -> 0x150); solve's are pinned. Not changed: Solver::solve (the reference search). The same rewrite there grew bench's thread entry, where it is inlined, by 60 to 771 bytes, depending on the form.
