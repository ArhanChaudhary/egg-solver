## Original experiment record

miri: run the unit tests under Miri; miri.sh

Miri interprets the code and checks unsafe operations for undefined
behavior (out-of-bounds or misaligned accesses, provenance, uninitialized
memory) and threads for data races. It cannot run inline asm nor every
mmap flag, so:
- coord.rs: under `cfg(miri)`, the asm `pext`s of `cocsep`/`cocsep3` and
  the asm `vpmovmskb` of `edge_parts_sym_raw` are the same operations as
  intrinsics. Normal builds are unchanged (identical disassembly of
  `bench`, addresses aside).
- tables.rs: `Mem::anon` maps without `MAP_NORESERVE` and skips
  `madvise` under Miri; `cocsep_classes_and_distribution` is ignored there
  (`Cocsep::generate` takes over 30 minutes).
- Fewer samples under Miri in two tests.

`miri.sh` runs the cubie model, SIMD cube operations, coordinates, the
hot index path, the job sorts and the share-protocol tests (many
scheduler seeds), in parallel processes (about 20 minutes on 6 cores).

Findings: no undefined behavior in the code Miri runs. The parallel
sort passes its buffers as integers (`Bufs::*_ptr: usize`, cast back to
pointers in the tasks), which Miri's strict provenance rejects and which
keeps it from checking those accesses; miri.sh runs that test with
permissive provenance.
