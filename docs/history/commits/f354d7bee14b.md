## Original experiment record

c4: sticky inverse side for INV jobs (negative, -3.14% vs -3.87% nodes)

Jobs whose statistics came from an inverse-side whole run (INV) are split
on the inverse side in the next iteration (partial runs with
root.normal = false, todo = mm_i & mask, tw on that side), instead of
running whole, ranked by their best child. The sticky part is the INV
branch of build_runs' allowed mask and root.normal = !inv in setup_job;
the diff also carries the rest of that time's experimental worktree.

Why: let INV jobs use their per-child statistics too.

Nodes vs main on random:1000:2026 (pj2, free side):

| config                         | nodes vs main |
|--------------------------------|---------------|
| INV jobs run whole by max      | -3.87%        |
| sticky inverse (this patch)    | -3.14%        |
| sticky inverse, fb1            | -2.97%        |
| whole by max, pj5              | -3.36%        |
| sticky inverse, pj5            | -2.60%        |

48-thread and 1-thread solves/s: not measured.

Conclusion: worse. Splitting on the inverse side costs 18 root children
instead of 15, and an INV job's best children are better run together.
Superseded by branching every job root on the normal side (-5.74%
combined).

worktree against c4 WIP commit 93e4566 ("WIP c4 v2", reachable from this
branch); applies cleanly.
