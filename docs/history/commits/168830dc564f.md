## Original experiment record

neg: stack placement pinned without pinning the hot code's page offset

This is s9-pin with the hot sections aligned to 64 bytes again, as on main
(STREAM_LINE and SHARE_LINE 0, `.p2align 6`). The stack data is pinned at
7608a28's offsets (pinF). The added functions grow `.eh_frame`, and that
moves `.text`: `stream_thread` goes from 0x24290 to 0x24390 and `rounds`
in `solve` from 0x1f310 to 0x1f390.

1T stream (stream 10 60 1 24), paired against 7608a28 (pinF/main):
0.982 0.985 0.992 0.992 (median -1.2%). 1T share
(random:400:2026 share): 0.995 1.000 1.027 (pinF).
48T, 3 holds (17f / depth17 ms, bshare, stream): stream -1.8% and -1.0%,
bshare +2.6% and -0.6%.
Same binary, only the stream frame moved (exp4 runtime pad: frame base at
page offset 0xfc0 vs 0x5c0): +0.6 -0.1 +0.8%. So the loss is the code
shift, not the stack placement.

The page-top variant (pinA: share DEPTH 0, so `rounds` is entered at 0xff8;
stream DEPTH 0, so its frame base is at 0xfc0; code shifted by +0x80):
- 1T stream: 7 pairs, median -0.8%, 6 of 7 negative.
- 1T share: 7 pairs, +0.7%.
- 48T -c 1, 4 holds: per cube -0.3% / -0.6%.
