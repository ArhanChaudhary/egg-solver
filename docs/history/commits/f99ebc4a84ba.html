Packed 3-byte cocsep entries on a huge page; shorter index chain

The hot cocsep data is now packed to 3 bytes per entry, class<<10 | ttrep<<4 | depth, read as an unaligned u32 at 3i (459 KB instead of 612 KB of L2 footprint). The packed table lives in its own 2 MiB anonymous mapping so it is backed by one transparent huge page (one TLB entry instead of ~150). The u32 data table stays for gen.rs/tests.

index_from_parts computes (class*70+msplit) << (k+9) | (eo>>(11-k))<<9 | eslot directly instead of building the h11 key and reducing it, cutting the chain after the RANK8 load from ~8 ops to 4. The unit test checks it against reduce_key for every k in 0..=11.

Search is unchanged (depth18: 3607979 nodes/cube, lengths 18:100).
