## Original experiment record

tables, cubie: thiserror error types for table files and facelets

The library returned ad-hoc errors: std::io::Error::other(format!(..)) and
InvalidData strings for table loading and validation, and String for
CubieCube::from_facelets. They are now enums (thiserror):

* tables::TableError (tables::file): read_meta, H48Table::open,
  open_with, from_file_memory, Trailer::parse, read_trailer and
  write_trailer. File errors carry the path; I/O errors are the source
  (Io, NoMeta), not repeated in the message, so an anyhow chain prints
  each once. The messages are the old ones.
* cubie::FaceletError: from_facelets (same messages; the wasm module
  passes them on as before with to_string).

Memory::map_file and map_read_only (memory, not table, APIs) and
H48Table::save keep std::io::Result. thiserror is a proc macro: no code
on any search path (the errors are built on the open/validate paths
only). build.rs includes src/cubie.rs, so thiserror is a build-dependency
too.
