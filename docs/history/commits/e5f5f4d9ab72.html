NEGATIVE c8: c7's child ordering ported to share mode (not merged)

Nodes fall (-8% at 8T share:1, -13% solve -c 1 at 48T; lengths identical, 0 BAD, tests pass), but latency rises: solve -c 1 at 48T on 500 random states +2.4..+3.8% (18-move +2.5%, 19-move +8%); bench share:1 at 8T -1.7% solves/s. The final iteration finds solutions sooner (0.71 -> 0.48 ms into T=18), but the run-list build costs 0.2-0.45 ms vs the base sort's 0.11 ms, code recording and per-node costs add ~2% and ~7%, and 19-move cubes' exhaustive T=18 needs ~2x the runs. Variant with per-thread records / build-time groups: worse (+4.9..+8.4%). Ideas left (in the patch header): build the run list during T=17's tail, split only at likely-final iterations, lighter setup for whole-job runs. Patches and the final WIP diff are in negatives/.
