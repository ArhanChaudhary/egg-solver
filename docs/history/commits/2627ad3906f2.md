## Original experiment record

enforce no panics: crate lints, a scan for asserts in check.sh

The user asked that the code have no intentional panicking paths; the
earlier commits removed them. This keeps it so:

* At every crate root (lib, cubeopt, bench, gen, solve, build.rs,
  wasm/src/lib.rs, wasm/build.rs, benches/kernels.rs):
  #![cfg_attr(not(test), deny(clippy::unwrap_used, clippy::expect_used,
  clippy::panic, clippy::unreachable, clippy::todo,
  clippy::unimplemented))]. Test builds, tests/ and examples/ are not
  linted.
* No lint flags assert!: tests/no_runtime_panics.rs scans the shipped
  sources (src/, build.rs, wasm/src, wasm/build.rs, benches) with
  comments, strings and char literals blanked, leaves out #[cfg(test)] /
  #[cfg(all(test, ..))] items, statements and fields and const/static
  initializers and const blocks (compile-time asserts are fine), and fails
  on assert!, assert_eq!, assert_ne!, panic!, unreachable!, todo!,
  unimplemented!, .unwrap() and .expect( in the rest, with file:line. A
  second test checks the scanner on a sample. check.sh runs it as its own
  step after cargo fmt. debug_assert! stays allowed (not in release
  builds).
* benches/kernels.rs prints an error instead of unwrapping.
