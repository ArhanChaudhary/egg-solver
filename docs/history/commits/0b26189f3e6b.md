## Original experiment record

m4: exhaustion test on live instead of the remaining todo (negative, neutral)

On the m4 stack: advance tests `live == 0` (todo minus the pending
skipped X' moves) instead of `node.todo == 0` after the skipped moves are
counted. The outcome is the same, and live is known a few cycles
earlier.

Why: this branch mispredicts at every pop and waits for the value just
noted; resolving it earlier makes its mispredicts cheaper (see
neg/m4-diag-brL-incl-c6).

48 threads (bench /mnt/huge/h11 stream 20 30 48 20, capped, interleaved,
3 runs, solves/s; measured as c9l against c9, the agent's build of the
near-final m4 stack):

| build              | run 1 | run 2 | run 3 | median |
|--------------------|-------|-------|-------|--------|
| c9 (m4 stack)      | 892.3 | 889.0 | 940.1 | 892.3  |
| c9 + live test     | 891.8 | 897.6 | 942.1 | 897.6  |

Change: -0.1, +1.0, +0.2% per run: within noise. Run 3 is a machine-wide
state shift for both builds. 1-thread solves/s: not recorded.

Conclusion: neutral. The pop branch still waits on the store-to-load
forwarded node fields. p5 later got it to resolve earlier by keeping the
depth and the top node's todo/lb/r in registers (regs, +2.7%, merged in
9caf0e2).
