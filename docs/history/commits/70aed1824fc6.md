## Original experiment record

m4: diagnostic, 50% random early-resolving branch per visit (negative, -13.2%)

Diagnostic, not a candidate. On top of c6 (the previous commit), each
lane visit executes a branch that is taken 50% of the time at random: an
xorshift LFSR in a register and an inline-asm test/jz. Its condition
comes from registers only, so it resolves early.

Why: calibrate what a mispredict costs in the lane loop (about one
mispredict per two visits).

48 threads (bench /mnt/huge/h11 stream 20 30 48 20, capped, interleaved,
3 runs, solves/s):

| build                      | run 1 | run 2 | run 3 | median |
|----------------------------|-------|-------|-------|--------|
| c6 (previous commit)       | 877.6 | 879.6 | 884.0 | 879.6  |
| c6 + early random branch   | 768.8 | 761.4 | 763.9 | 763.9  |
| c6 + late random branch    | 742.7 | 746.7 | 747.4 | 746.7  |

Change: -13.2% (early), about 21.7 cycles per mispredict by the agent's
estimate. 1-thread solves/s: not recorded.

Conclusion: a mispredict costs about 22 cycles even when it resolves
early. The late variant (neg/m4-diag-brL-incl-c6) costs about 28.

Source: scratchpad m4/neg-diag-brE-incl-c6.patch (cumulative: wip-c6 +
mk-diagbr.py E, against ff2b7a4). Recorded as two commits on ff2b7a4: c6,
then this increment; the branch's tree equals ff2b7a4 + the patch.
Numbers are the agent's own (not re-measured for this record). Not merged; recorded per the rule that every candidate gets a branch.
