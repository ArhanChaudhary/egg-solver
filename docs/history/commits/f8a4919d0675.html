lanes: fewer µops per generated child (lazy child cube, blsmsk count, move tables, early stores, index tweaks)

Five per-child instruction cuts in advance and the index path. Each has a clear mechanism; they were measured together (part of a stack).

  • Lazy child cube: advance computes only the looked-up cube, as one composition of operands selected by a per-move k-mask loaded from a table (Cube::child_lookup, HOT_TABLES.x_move_mask, pending_cube, replacing pending_moved / pending_other):
    • X moves: inv_mv[m] o b;
    • other moves: a o mv[m]. The other cube is computed only on the X pass path (resolve_other) and on a push (push_child / child_node take the cubes). This is a new angle on neg/m6-lazy-child-cube, whose mask came from m % 3 at the head of the index chain. It also replaces the stores of two pending cubes with one.
  • blsmsk count: todo & blsmsk(live) counts the skipped X' moves and the generated child with one popcount and clears them from todo with one andn. This is fewer µops than the bzhi count + nodes += 1 + blsr, unlike neg/m3-merged-node-count, which added a masked count on the pop path.
  • Move tables: a move's face and kind (and the face mask at a pop) come from HOT_TABLES (move_face, move_kind, move_keep), with no imul/shr/lea/sub.
  • Early stores: pending_face, pending_other_bound, phase and the node count are written before the index computation, so that they are not live across it. A child pruned by its corner bound reads them back, volatile. This removes the spill and reload of the node counter.
  • Index: Tinv's eo is folded into the first xor of edge_parts_sym, which becomes a vpternlog with a memory operand: no p load into a register, no z ^ p. SymEdge entries (classes, perm, perm_eo) are 128 bytes, so the entry offset stays one masked, scaled index. msplit's pext and the asm vpmovmskb output are 64-bit (no zero extensions).
  • Table reads in the hot path use get_unchecked (bounds known: moves are below 18), each with a one-line SAFETY comment.

Instructions per node on an older base (cachegrind, x86-64-v3 build, random:20:2026, 1T): 148.79 -> 140.25 (-5.7%). On v3 the k-mask blends fall back to vpblendvb with a broadcast mask, so the native cut is larger. (Cachegrind no longer runs: next_run uses AVX-512 unconditionally, SIGILL under valgrind.)

The search is unchanged. verify.sh on this build: nodes/cube 3058198 lookups/cube 2588380 lengths 15:1 16:35 17:270 18:662 19:32 nodes/cube 3644301 lookups/cube 3084160 lengths 18:100 (equal to main's). check.sh passes (exit 0, pedantic enforced).
