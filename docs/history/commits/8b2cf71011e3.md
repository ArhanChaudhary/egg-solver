## Original experiment record

Load the pending value before the phase dispatch; select po; one static for hot tables

From the m3 micro-optimisation round (mispredict-driven):

- run_lanes loads the lane's pending lookup value (`pending_value`) before
  the `match phase` dispatch, so a dispatch mispredict no longer delays
  the table load; resolve_other/resolve_moved take the value as argument.
- advance selects po = select_unpredictable(half, lo, tw): LLVM otherwise
  branched on `half` to skip the tw load.
- The small hot-path tables (MOVES, MOVES_ORI, INV_MOVES, SYM_EDGE, CO_LO,
  CO_HI, ESLOT, RANK8) live in one 64-byte-aligned static `TABS`, so all
  accesses share one base register (x86 has no RIP-relative indexed
  addressing; separate statics cost an lea each per use). The generated
  tables became consts feeding TABS; the old statics remain for other
  users.
