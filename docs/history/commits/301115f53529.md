## Original experiment record

cubie, coord: descriptive names and docs

Readability sweep of the cube model and the coordinates (renames are
listed in s8-rename-map.md/.sed in the agents' scratchpad).
- cubie: `CubieCube` fields `corner_perm`, `corner_orient`, `edge_perm`,
  `edge_orient` (were cp/co/ep/eo); `mul` -> `compose` (as
  `simd::Cube::compose`); `invert_co` -> `negate_corner_orient` (also on
  `simd::Cube`); `Sym` -> `Symmetry` with `matrix`, `cube`, `cube_inverse`;
  `sym_inverse_table` -> `symmetry_inverses`; the sticker model's `Mat`,
  `V3`, `det3`, `axis_vec`, `Sticker {p, n}` spelled out. `parse_moves`
  uses `Peekable::next_if` (same behaviour; a test pins it).
- coord: `binom`/`comb_rank`/`mk_*` -> `binomial`/`colex_rank`/`*_table`;
  `cocsep3` -> `cocsep_x3`; `CO_LO_T`/`CO_HI_T` -> `CO_LOW`/`CO_HIGH`; the
  two pexts shared by `cocsep` and `cocsep_x3` are one `corner_fields`
  helper; `cube_from_edge_key` builds through the new `Cube::from_bytes`.
- module overviews say what a coordinate and a pruning table are, item
  docs are one line, tricks (pext/movemask, the 27720 exponent, the tetrad
  mask) get a short why.
