## Original experiment record

share: typed pointers for the build tasks' buffers

The tasks of a staged build write disjoint parts of shared buffers
through copies of the buffers' start addresses. `Bufs` kept these as
`usize` and the tasks cast them back to pointers. Integers carry no
provenance, so Miri's strict provenance rejects the casts, and miri.sh
ran the staged-sort test with permissive provenance, which does not
check those accesses against the buffers.

The copies are now `TaskPtr<T>`: a `*mut T` in a wrapper that is Send
and Sync (the build stages order the accesses, as before). The machine
code does the same work.

miri.sh now runs the staged-sort test with strict provenance like the
others. Miri (-Zmiri-strict-provenance -Zmiri-symbolic-alignment-check)
passes lanes::share::tests::staged_sort_matches_sort_jobs (the staged
sort against `sort_jobs`, 8192..43254 jobs) and
lanes::share::tests::share_* with scheduler seeds 0..8.

Measured on main 595e424 (before c8's abce87c, which changes only
lanes.rs; the share.rs diff is the same), h11 table, random_state =
cube_solver_test dataset/random_state.txt (500 cubes), every binary
built in the same folder. 48 threads: paired, i.e. 7 exclusive holds,
each running every binary of the series back to back after the quiet

default). 1 thread: 6 runs; the binaries of a run ran at once in L3
