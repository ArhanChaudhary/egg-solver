## Original experiment record

p5: bucket-fifo with prefetch of the next lanes' state (negative, -2.5% 1T vs bucket-fifo)

On top of bucket-fifo (the previous commit, = neg/p5-bucket-fifo):
software prefetch of the next lanes' state (header lines and top node),
since bucketing makes the lane visit order irregular.

Why: test whether lane-state locality is what bucketing loses.

1 thread (stream 3 12 1 20, 2 runs, solves/s):

| build                      | run 1 | run 2 |
|----------------------------|-------|-------|
| main 35c608c               | 19.42 | 19.58 |
| bucket-fifo                | 18.08 | 18.00 |
| bucket-fifo + lane prefetch| 17.58 | 17.58 |

Change: -2.5% vs bucket-fifo (-9.8% vs main). 48-thread solves/s: not
recorded.

Conclusion: worse. Lane-state locality is not the problem; the prefetches
are only extra work.

35c608c). Recorded on top of neg/p5-bucket-fifo as its increment; the
branch's tree equals 35c608c + the patch.
