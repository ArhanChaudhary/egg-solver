## Original experiment record

lanes: count nodes into Lane::stats where they are reached

NEGATIVE (not for merge). Against cb8cb70 (= fc6d9c9's tree).

advance counted the generated and the skipped nodes in a local `nodes`
and added it to `stats.nodes` on return; LLVM keeps it in a register,
spills it across the index computation and reloads it at the return.
Here every site adds to `stats.nodes` directly (the skipped X' moves at
the exhausted-node exit, skipped + 1 at each generated child), so no
counter is live across the loop. Search identical (cachegrind run:
same nodes/cube).

Instructions per node (cachegrind, x86-64-v3 build, random:20:2026, 1
thread, 20 lanes): 148.79 -> 145.73 (-2.1%).

But it is slower. LLVM loads `stats.nodes` at the loop top and stores it
after the count; the read-modify-write through memory (and the new
register allocation) costs more than the spill it removes.
