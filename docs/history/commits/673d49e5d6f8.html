tables, gen: any table size h0..h11 generated directly; self-describing table files

User request: "make your solver work with multiple pruning tables sizes so i dont need 62gb and can run it on my laptop". gen <k> auto <file> now builds hk for every k without h11, in about the table's own size of memory, and solve/bench open a table file from any file system.

gen::dfs (new). For 0 < k < 11 the hk index is not a coset coordinate (the eo bits it drops are not those of a union of slices), so it cannot be BFS'd on its own indices: each entry is the minimum depth of the h11 cosets it covers (until now: derived during an h11 BFS, which needs the 58 GiB h11). The generator enumerates the h11 cosets up to depth base + 2 instead:

  • a BFS on h11 entries in sorted vectors up to depth 8 (7.4M entries, its levels equal the h11 BFS log: 1/4/34/333/3815/45382/548562/6839723);
  • one depth-first pass per further depth L from every depth-8 entry, one per self-symmetry orbit (symmetry at the root), over canonical move sequences; children of the roots that are in the prefix are pruned;
  • leaves are marked "set if unvisited": the passes run in increasing L, so an entry's first mark is its minimum and all marks of a pass write the same code (plain atomic ANDs, no CAS), through a 32-deep prefetched write ring per thread (batched prefetched writes);
  • group minima of depths <= base during the passes, the others (never read) in a final pass, which gives the BFS generators' tables byte for byte;
  • --parts N generates N row ranges in turn (memory 1/N of the table, time up to N times: the DFS is shared, only leaves of other classes are cut). Cost depends on the base, not on k: ~2.6e11 leaves for base 10, 1/13 of that for base 9, 1/170 for base 8; ~9.5 ns per leaf per Zen 5 thread, nearly independent of the table size (h0 30 MB vs h5 970 MB: 3.0 vs 3.7 s for the same pass), so compute bound. h0 and h11 keep the scanning BFS (true coordinates; forward/backward per level).

gen::collapse (new): hk from a larger k of the same base (min over the covered rows), and table comparison (gen derive, gen compare).

Validation:

  • full-size h0 base 8 by DFS == by BFS, byte for byte (incl. group minima);
  • h7 base 9 (direct, no h11) vs /mnt/huge/h7 (made by the h11 BFS): all 15,048,633,600 codes identical; group minima identical wherever read (18,506 unread ones differ: groups whose minimum is 12, which the h11-derived table records and a base-9 one leaves at 15);
  • h8 base 10 in 2 parts (3.86 GiB peak) vs /mnt/huge/h8: byte-identical;
  • h9 base 10 in 4 parts vs the collapse of /mnt/huge/h11: byte-identical (60,194,534,400 entries, all group minima);
  • h7 base 10 (direct) vs the collapse of h11: byte-identical;
  • h8 base 9 (2 parts): codes 0+1 and 2 = 1,051,580,076 and 8,136,022,157, exactly h8 base 10's codes 0 and 1; h4..h7 base 8 (direct), base 9 (from the direct h7) and base 10 (from h11) are consistent in the same way;
  • random_state (500 cubes): per-cube optimal lengths with the direct h7 and h8 identical to h11's (stream mode);
  • new tests: DFS h0 == BFS h0 for prefix depths 1, 2, 5; h2 vs brute force over all positions within 5 moves (codes, group minima, nothing too low); h3 in 3 and in 7 parts == h3; collapse h3 -> h2 and h3 -> h0; trailer round trip, bad layouts refused, the data never written, checksums from parts.

Table files (tables::file, new): the data at offset 0 (mappable as is), then a 4 KiB text trailer in the last 4 KiB of the file: layout h48, k, base, data bytes, code distribution, checksum (per-1 MiB-chunk hashes, so parts need no second pass). Unknown keys are ignored but another layout is refused (room for e.g. a parity-bit variant). The trailer fits in the slack of the existing hugetlbfs files (h11: 15 MB), so `gen stamp

` adds one in place (refuses to touch the data region, reads it back); `gen check` verifies distribution and checksum. Meta lookup: trailer, else `.meta`, else the legacy build-dir `.hugemeta` (/mnt/huge, until stamped). Loading: hugetlbfs and /dev/shm mapped (as before); other files copied into anonymous THP memory (Linux default, now dropped from the page cache as copied) or mapped read-only with MADV_HUGEPAGE (default off Linux), `CUBEOPT_LOAD=auto|map|copy`, `CUBEOPT_PREFAULT=1|0` (map: fault it all in at open with parallel MADV_POPULATE_READ, or on first use).

bench <table> tune: 1T and all-core stream sweeps over 8..48 lanes, saved to <table>.tune, read by solve and bench as their default lanes (else tables::file::untuned_lanes(k)).
