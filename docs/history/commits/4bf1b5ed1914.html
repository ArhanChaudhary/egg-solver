Merge opt/shm1: tables in System V shared memory (--shm), like vcube (user request)

solve/bench/cubeopt --shm (= --load shm), solve --shm-load / --shm-remove; auto uses a matching segment. Key 'co'+k+base (--shm-key overrides); the segment holds the file's bytes with its trailer last (written after the copy's checksum is checked), read-only perms + SHM_RDONLY attach; every attach compares trailers (other table: refuse/skip; no trailer: wait or reload). Pages 1 GiB -> 2 MiB -> 4 KiB with permission/pool/ shmmax checks and notes; 4 KiB warns. Memory preflight via cli::preflight. Linux only. h7 1T: shm 1G = hugetlbfs map 1G (2.267 = 2.267); shm 4K -27% (1T) / -31% (48T) vs 1G map; 48T shm 1G vs map 1G -2.1% (within noise). Startup: 1G attach 0.00 s vs copy from disk 28 s. Hot code identical (rounds at page offset 0x310); h8 node counts identical. check.sh OK (memory-capped run). 1 GiB pages need vm.hugetlb_shm_group (README 'Shared memory').
