m3: compile-time k = 11 copy of the lane engine (negative, -2.1%)

run_lanes dispatches to an #[inline(always)] run_lanes_k with s.with_k(11) when the table has k = 11 (h11), so the inlined index computation sees k as a constant: constant shifts, fewer live registers. Adds Solver::with_k and Solver::k.

Why: k is fixed for the whole run but costs register shifts in every index computation.

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, interleaved, 3 runs, solves/s):

Change: -2.1% (median); every run lower (-1.6, -2.1, -1.6%). Hot-loop instructions per node (callgrind, znver5 build without AVX-512, random:16:2026, 1 thread): 193.55 -> 192.47 (-0.6%). 1-thread solves/s: not recorded.

Conclusion: the constant k saves only about one instruction per node, and the second copy of the engine changes code layout, which costs more.
