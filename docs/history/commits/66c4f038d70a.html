scripts/pgo-solve.sh: profile-guided build of solve (1T -2.1% ms/cube; 48T -c 1 neutral)

The perf book's PGO item, re-measured with pinned hot-loop pads. PGO slows the stream loop at every pad (neg/pb1-pgo-stream, best pad -0.2% at 1T), but it speeds up the share loop, which is all that solve runs. So this adds a script that builds solve alone with PGO; bench, the default cargo build and the NEON/wasm builds are untouched.

scripts/pgo-solve.sh

[threads]:

  1. instrumented solve (-Cprofile-generate, added to the repo's own per-target rustflags with --config target.'cfg(all())'.rustflags, so target-cpu=native stays: the profile-use build's Worker::rounds is instruction-identical to one built with RUSTFLAGS="-C target-cpu=native -Cprofile-use=...");
  2. training on the table, 8 threads: -c 1 on 150 and -c 0 on 300 scrambles of 40 random moves made by the script (Park-Miller, seed 20261105; gawk and mawk give the same file). No cube from cube_solver_test's datasets, testdata/ or bench's random:N:SEED sets;
  3. llvm-profdata merge (rustup's llvm-tools), -Cprofile-use build at share pad 0 (PGO moved the loop's best pad from 16 to 0; sweep in the script's comment). The profile is regenerated by the script (~150 KB, not deterministic), not committed. Training command used for the numbers below (585b3b6, CPUs 0-7): OUT=/data/agents/pb1/pgo585 scripts/pgo-solve.sh /mnt/huge/h11 8 (150 + 300 training cubes, 0 BAD; ~2.8M nodes/cube, like random states).
