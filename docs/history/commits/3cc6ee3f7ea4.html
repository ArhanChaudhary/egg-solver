lanes: descriptive field and item names

The first of three lanes.rs commits (fields and items, then locals, then docs), each instruction-identical in the hot loops, so that a regression is easy to bisect.

  • Node {a, b, lo, mm_o, r, lb, m, m_normal, tw} -> {moved, other, other_side_bound, other_moves, remaining_depth, lower_bound, mv, mv_normal, twin_values}; lanes' Job {ln, li} -> {normal_bound, inverse_bound}.
  • Lane: root, root_inverse, run_state, depth, job_stat, child_stats, and the pending child's pending_moved, pending_other, pending_move, pending_face, pending_index, pending_corner_bound, pending_other_bound (were root_c, root_ci, rs, sp, heur, cheur, k_*).
  • JobX -> ChildOrder {codes, twin_values, done}; RunState's child_orders, current_job, current_children.
  • items: quantize, quantize18, codes_above, max_code, stat_terms, STAT_TERMS, STAT_PAIRS (and HotTables::stat_pairs), max_child_bound, unknown_twins, FIRST_FRACTION, MERGE_CODES; main's newer UNSEEN_CODE keeps its name, and its test becomes quantize18_codes_unseen_children.
  • share.rs: only the uses of these (mechanical; the map's field rules also cover l6's receivers scratch, lane, sl.lane, to.lane).
