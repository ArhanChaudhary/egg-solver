lanes: generate a pushed child's first child from registers

When resolve_moved pushes a child, advance() then reloaded the just-written 128-byte node through store forwarding before generating its first child. A fresh node has no bound (lb = 0) and no skipped moves, and its first move is an X move (move masks are whole faces, less half turns), which looks up the other side first. push_advance() generates that child directly from the node value (cubes, todo, r in registers); the rare kinds (r1 == 0, r1 > maxval, empty todo) and the cocsep-depth prune fall back to an out-of-line advance (advance_cold).

Search unchanged (verify.sh identical to 35c608c: nodes/cube 3295521 lookups/cube 2785769, lengths 15:1 16:35 17:270 18:662 19:32; depth18 nodes/cube 3607979 lookups/cube 3053364, lengths 18:100). check.sh: exit 0.
