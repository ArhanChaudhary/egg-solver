## Original experiment record

p5: diagnostic, bucket-fifo's visit order with main's dispatch (negative, -4.5% 1T vs identity)

Diagnostic, not a candidate. As neg/p5-diag-perm-identity, but each
round's order is a stable partition by a random bit (P = 0.71). That
gives the revisit-gap distribution of bucket-fifo while keeping main's
(unpredictable) phase dispatch.

Why: measure what the reorder costs on its own.

1 thread (stream 3 12 1 20, 2 runs, solves/s):

| build                                  | run 1 | run 2 |
|----------------------------------------|-------|-------|
| main 35c608c                           | 19.42 | 19.58 |
| pointer arrays, identity order         | 18.42 | 18.42 |
| pointer arrays, random partition       | 17.58 | 17.25 |
| bucket-fifo (same order, no dispatch)  | 18.08 | 18.00 |

Change: -4.5% vs identity order (run 1; -5.4% on the mean of both).
48-thread solves/s: not recorded.

Conclusion: the reorder alone costs about 4.5%, and removing the dispatch
(bucket-fifo vs this) gains only about 4%. Every order that groups
phases moves lanes within the round, so each lane's revisit gap varies
around 20 visits. That costs more than the dispatch.

Source: scratchpad p5/neg-diag-perm-random.patch, made against 35c608c;
applies cleanly.
