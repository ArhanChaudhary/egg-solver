share: Pad is crossbeam's CachePadded

The share mode keeps its shared atomics, rarely written fields and free lists on cache lines of their own (Pad, l6-share-2: bench share 787 vs 845/s without it). Pad was our own #[repr(align(128))] newtype with a Deref; it is now an alias of crossbeam_utils::CachePadded, the usual crate for this. CachePadded is align(128) on x86-64 (the spatial prefetcher pulls 64-byte lines in pairs) and aarch64 (128-byte lines on Apple cores), so the layout is the same, and so is the code: every cubeopt/bench/solve function of the release build has the same instructions as on main (addresses and call targets stripped), except solve::main (Pool::new inlined), where two registers swap. On wasm32 CachePadded is align(64) (was 128). The call sites stay: Pad<T> is kept as the alias, Pad(x) -> Pad::new(x), and two .0 become derefs.

Not a speedup (the same code), measured as neutral:

  • Hot functions against 7608a28 (= 3a9a50a on x86): Worker::rounds the same code at the same line offset (16), the share thread closures (solve, bench::share_thread) frame 0x1f40, bench::stream_thread frame 0x1c80, all unchanged.
  • Search identical (verify.sh on the whole series: nodes/cube 3058198 lookups/cube 2588380, lengths 15:1 16:35 17:270 18:662 19:32; 3644301 3084160, 18:100); no bad solutions.
