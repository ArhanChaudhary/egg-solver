## Original experiment record

lanes: compile-time size checks of Node, Job and ChildOrder (x86-64)

The comments on these types state their sizes (Node two cache lines, Job
12 bytes, ChildOrder 32 bytes), and kernel decisions depend on them (Node
96 bytes was -2.9%, neg/m6-node-96-bytes). A const assertion makes a field
that grows one of them a compile error instead of a silent slowdown (the
perf book's "Type Sizes / Avoiding Regressions"; sizes measured with
-Zprint-type-sizes on nightly-2026-11-03, target-cpu=native). Only on
x86-64, where they were measured.

No code is generated: built from the same folder as main 585b3b6, bench
and solve have byte-identical .text and .rodata sections (objcopy + cmp);
the files differ only in their debug line tables (10 lines added).
