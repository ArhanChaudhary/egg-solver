Eager sibling-face pruning, X' skip mask, branch-free child setup

Per-node cost is dominated by branch mispredictions (~22 cycles each on Zen 5; sensitivity builds: index-chain latency and extra uops are cheap, memory/TLB are not limiting). A TAGE simulation of the lane engine's branch trace put main at ~1.14 mispredicts/node. This change removes the data-dependent per-child branches:

  • Sibling-face pruning happens when a bound is noted (note_value and the parent update on pop): the face's remaining moves are dropped from todo branchlessly. Exact because fmax only grows and r is fixed. advance no longer iterates over pruned siblings.
  • X' children pruned through their X sibling's other-side value (tw) are marked in Node::skip when X is pruned, and counted (popcount) when reached without being generated.
  • The remaining children are set up without branching on X/X2/X': X looks up the other side (b2); X2 and X' look up the moved side (a2) with lo/tw as the known other-side value, both <= r1 by the NO_HALF masks and the skip mask (debug_assert; a debug-assertions run passed).

Advance iterations per node 1.365 -> ~0.89; branches/node (cachegrind) 17.8 -> 13.6. Search is unchanged: random:1000:2026 3295521 nodes/cube, 2785769 lookups/cube; depth18 3607979 / 3053364, lengths 18:100.
