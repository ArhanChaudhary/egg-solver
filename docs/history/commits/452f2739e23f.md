## Original experiment record

m4: diagnostic, one extra index computation per generated node (negative, -13%)

Diagnostic, not a candidate. In advance, every generated child also
computes the table index of its moved-side cube (s.index(a2)) and stores
it (k_idx2) so the computation is not optimized away; no prefetch.

Why: price the index work that paired lookups (neg/m4-pair-lookups) would
add.

48 threads (bench /mnt/huge/h11 stream 20 30 48 20, capped, interleaved,
2 runs, solves/s; same runs as the paired-lookup A/B):

| build              | run 1 | run 2 | mean  |
|--------------------|-------|-------|-------|
| main ff2b7a4       | 836.3 | 819.0 | 827.7 |
| + extra index      | 719.8 | 718.8 | 719.3 |
| paired lookups     | 491.1 | 489.9 | 490.5 |

Change: -13.1% (mean); per run -13.9, -12.2%.
1-thread solves/s: not recorded.

Conclusion: one index computation is about 13% of a node's cost, so
duplicating it per child cannot pay.

Source: scratchpad m4/neg-diag-extra-index.patch (= diag-idx), made
against ff2b7a4; applies cleanly.
