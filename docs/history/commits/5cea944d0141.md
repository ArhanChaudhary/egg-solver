## Original experiment record

Single-pass round-robin lane scheduler; 16 lanes by default

Replace the 3-phase lockstep loop (advance all, resolve all A, resolve all
B) with a single round-robin pass: each lane visit resolves the lookup the
lane issued on its previous visit and then advances it to its next lookup.
Each miss now gets a whole round of slack (~0.5us vs ~145ns latency) while
only about one miss per lane is in flight, instead of bursts of up to 32
prefetches that exceed the core's miss buffers and leave each lookup only
one phase of slack. Found by the search-analysis subagent, which also
measured that the search is now ~86% compute-bound (record/replay of
lookups: 22.3 ns/node compute vs 25.9 ns/node measured).

Lane-count scan (./bench.sh, 1 run each): 12: 564.6, 16: 572.9, 24: 570.1.
