tables, gen, parallel: errors instead of panics

The user asked that the code have no intentional panicking paths:

  • Memory::anonymous returns TableError::Alloc when mmap (or the allocator) fails; words() and bytes() return TooLargeForSlice instead of asserting (32-bit targets). Memory::layout is an Option.
  • Cocsep::generate checks the BFS's counts and depths and returns TableError::CocsepModel instead of assert_eq!/assert!/unwrap; the packed entries are written as 3-byte arrays (no copy_from_slice, no slicing).
  • LoadOptions::from_env returns TableError::BadEnv for a bad CUBEOPT_LOAD / CUBEOPT_PREFAULT instead of panicking (H48Table::open passes it on).
  • read_parallel and prefault: a thread that cannot be started reads its range on the calling thread; read errors and thread panics come back as io errors (was expect("read table") and implicit panics of thread::scope). fadvise is skipped for offsets beyond off_t.
  • H48Table::distribution, trailer, save (and the new data()) return errors; from_file_memory's pieces check their range.
  • parallel::on_threads runs a share whose thread cannot be started (or that the runner did not run) on the calling thread, and returns WorkerPanicked if a worker panicked (was join().unwrap() and expect). The wasm runner runs nested jobs and shares without a thread inline (was assert! and thread::spawn's panic).
  • gen: Generator::run, dfs::Generator::new/generate, collapse::derive and compare, generate and generate_table check their arguments and return TableError::Generate / TooLarge instead of asserting; Generator's derived tables are word slices.
  • tables/file.rs: no unwraps of constant conversions; checksum lanes by as_chunks.
  • The bins and the wasm module pass the errors on (gen's sync_file_range and fadvise ranges are skipped if they do not fit, instead of unwrap).
