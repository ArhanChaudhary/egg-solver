Original experiment record

binaries: clap, anyhow, log/env_logger, --json, progress bars, completions

User request: "enhance your binary with common and ubiqutious crates. Clap for example". solve, bench, gen and cubeopt hand-parsed std::env::args and panicked or exited on errors. Now:

  • clap (derive): --help (and -h), --version, typed and range-checked values (threads and lanes >= 1, k 0..11, base 0..12, seconds, K:BASE:PATH), environment fallbacks (CUBEOPT_TABLE, CUBEOPT_THREADS, and CUBEOPT_LOAD / CUBEOPT_PREFAULT as --load / --prefault, now validated: they panicked in LoadOptions::from_env). gen has subcommands (generate, stamp, check, derive, compare; gen <k> <base> <out> is still generate), bench too (stream, batch, tune).
  • Backward compatible: every form that the scripts ($P/bin, verify.sh, main-ab, l6, f1's final-compare.sh and runtest.sh), README and bench.sh use parses as before and prints the same stdout (and stderr). bench's positional form (bench <table> stream 20 30 48 24, bench <table> random:1000:2026 1000 48 20 share, ... share:1, bench <table> tune) is rewritten to the subcommand form before parsing (legacy, with a unit test).
  • anyhow: errors with context (solve: cannot open table x: x: no table trailer, and no meta file x.meta: No such file or directory), no panics on bad input. Exit statuses as before: 2 for usage errors and unusable input (cli::BadInput: a scramble that does not parse, a table that does not open: solve gave 2, bench and cubeopt aborted), 1 for other errors, a BAD solution, a failed check (gen as before).
  • --json: JSON lines (serde_json) from solve (one object per cube, flushed per line as the text lines are, then the total), bench (one object per result) and gen check. The binaries print it: serde_json in the library crate would bring its PartialEq<Value> for u8 impls into the library's tests and break inference there (assert_eq!(v, []) in share.rs).
  • log + env_logger: -v (or RUST_LOG) logs to stderr how the table was loaded (map/copy, prefault), its size and load time, its pages (1 GiB hugetlbfs, or how much is in transparent huge pages, from /proc/self/smaps), and the threads and lanes (and where the lanes came from). Nothing is logged without -v: stderr is as before.
  • indicatif: on a terminal, gen shows a progress bar of the current step (BFS level or depth-first pass, by chunks; the generators report through the new cubeopt::gen::progress, an atomic load per chunk when unused) and a spinner while it reads a whole table (check, stamp, derive, compare). Not on a pipe or file: logs get the same lines as before.
  • clap_complete: hidden --completions (bash, zsh, fish, elvish, powershell).

The crates are optional dependencies behind a default cli feature; the bins and tests/cli.rs require it, cubeopt::cli (what the binaries share) exists only with it, and the wasm module uses default-features = false (its build does not change). The library's search code has no new dependency.

Considered and not taken: rand (the random:N:SEED sets and verify.sh's counts depend on our Rng), memmap2 (the hugetlbfs and populate handling), rayon (our threads), clap-verbosity-flag (a counted -v is three lines), tracing (log is enough: no spans across threads wanted), color-eyre / miette (anyhow's chain is enough for a CLI), serde in the library (the JSON types are the binaries'), serde_json in wasm/ (see below), humantime (env_logger's default timestamps: an elapsed-seconds prefix is more useful here).

The wasm module's hand-rolled JSON stays: its four objects need no escaping (move notation, facelet letters, numbers), and its fixed number formats ({:.6} seconds, {:.4} rate) are the JS contract that serde_json would print differently (shortest round-trip floats); serde would also be two more crates in the module for no change in what it sends. The module builds with cubeopt's default-features = false (none of the CLI crates); its only change here is from_facelets(..).map_err(|e| e.to_string()).

Tests: tests/cli.rs makes h0 with gen 0 8 and runs every legacy form against it (solve, bench stream/batch/random/share/share:1, cubeopt, gen generate/check/derive/compare/stamp), the subcommand forms (same counts as the legacy forms), --json, -v, the environment variables, --help, --version, completions, and the exit statuses.

check.sh passes, with /data/tools/bin on PATH (wasmtime library tests and bun wasm/test.mjs, both builds), and the criterion benches pass clippy (--features bench --benches).

Speed: no change to the search or the code that runs it. The parsing is all in main, before the threads start; bench's run/share_thread/ stream_thread/stream_throughput are unchanged text, and solve keeps s9's page pin (the .text.hot_share section and solve_all_pinned) as on main.

  • objdump vs main 0c4bfe2 (addresses normalized): Worker::rounds instruction-identical in solve (page offset 0x310, as main) and bench, bench::stream_thread identical (line offset 16, as main; its page offset moves 0x590 -> 0xa90, not pinned in bench). Frames (sub rsp) the same for every thread entry: solve's solve_all_pinned closure 0x1000, share::deeper 0x190, rounds 0x98; bench's run closure 0x700, share_thread 0xfc0, stream_thread 0xfc0. (The pinned closure and share_thread differ only in where one 3-instruction cold block, an allocation-failure call after the body, is placed; bench's run closure in stack slot numbers of its lanes = 0 path, the recursive solver.)
