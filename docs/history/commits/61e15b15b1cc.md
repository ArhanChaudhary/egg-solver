## Original experiment record

m4: sibling-face masks from a table, written as if/else (negative, -4.3%)

On top of c6 (the previous commit): the face-drop mask for sibling-face
pruning comes from a table, TABS.face_keep[f] (move mask without face f),
written as `if f > r { face_keep[f] } else { !0 }`. It replaces
`!(((f > r) as u32).wrapping_neg() & (7 << 3f))` in note_value and in the
parent update on pop.

Why: no mask construction per noted value.

48 threads (bench /mnt/huge/h11 stream 20 30 48 20, capped, interleaved,
3 runs, solves/s; c9 = c6 + phase-encoding, c10 = c9 + this change):

| build                  | run 1 | run 2 | run 3 | median |
|------------------------|-------|-------|-------|--------|
| c6 (previous commit)   | 877.6 | 879.6 | 884.0 | 879.6  |
| c6 + if/else face mask | 843.0 | 839.8 | 841.6 | 841.6  |
| c9                     | 894.0 | 896.3 | 896.8 | 896.3  |
| c10 = c9 + face mask   | 848.4 | 846.0 | 843.7 | 846.0  |

Change: -4.3% on c6, -5.6% on c9. 1-thread solves/s: not recorded.

Conclusion: LLVM turned the select-with-load into a branch on the
data-dependent face drop, adding a mispredicting branch per noted value.
With select_unpredictable the same idea is neutral
(neg/m4-fmask-on-stack).

increment; the branch's tree equals ff2b7a4 + the patch.
