## Original experiment record

tables: binary layout independent of the build folder

`meta_path` built the `.hugemeta` path of hugetlbfs tables with
`format!("{}/tables/...", env!("CARGO_MANIFEST_DIR"))`, so every binary
contained the absolute path of the source tree it was built from. Builds
of the same commit from folders of different path lengths then had
different data layouts: from /data/agents/lt and from
/data/agents/layout-test-with-a-much-longer-path, 225 bytes of .text
(displacements of .rodata references) differed. On this machine layout
alone moves benchmark results by 1-2%, so A/B comparisons between
binaries built in different worktrees were confounded (e.g. an agent's
1T "+1.7%" between a base and a pure rename turned out to be this).

The path is now copied at compile time into a fixed 256-byte static
(`BUILD_DIR`, read through `black_box` so the padded buffer is what the
binary contains). The same two builds now have byte-identical .text and
identical section addresses. Behaviour is unchanged (same meta files).
