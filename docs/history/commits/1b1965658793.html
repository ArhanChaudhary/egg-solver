Original experiment record

b2: branchless moved-side resolution (negative, -2.2%)

resolve_moved always writes the pending child into the stack and does sp += push (0 or 1) instead of branching on whether the moved side's value prunes the child. Incremental on the skip-sibling patch (7a173a1, merged as b90b706).

Why: per-node cost on Zen 5 was dominated by mispredicts (~22 cycles each), and the TAGE simulation of main put the moved-side prune at 0.114 mispredicts/node.

48 threads (bench /mnt/huge/h11 stream 20 30 48 16, interleaved, 3 runs, solves/s; skipk2 is skip-sibling with the same tree as b90b706, skipk9 is skipk2 + this change):

buildrun 1run 2run 3median
main fe58740677.3680.0669.4677.3
skipk2 (b90b706)774.1767.1776.5774.1
skipk9 (+ this)752.9758.8756.7756.7

Change: -2.2% (median).

Instructions per node (cachegrind, x86-64-v3 build, random:16:2026, 1 thread): 202.4 (skipk2) -> 212.2 (skipk9), +4.8%. 1-thread solves/s: not recorded.

Conclusion: slower. The unconditional 128-byte child write and the sp arithmetic add about 10 instructions per node, and the agent's TAGE simulation showed the pop branch's mispredicts rising: the removed branch carried history that helped predict it. (b2 notes that variants of this code swing by about +-3% between builds; this one is consistently negative in all three runs.)
