## Original experiment record

laptop: lanes per table size, README "Running on a laptop"

User request: "so i dont need 62gb and can run it on my laptop". With the
direct generator (any k) and the portable backends in place, this sets the
defaults that depend on the table size, measured, and documents the laptop
path.

Lanes per thread (`tables::file::untuned_lanes`, the default of `solve` and
`bench` unless `bench <table> tune` saved a `<table>.tune`): 40 up to h8,
32 for h9 and h10 (not measured: no RAM for them here), 24 for h11 (as
before). Smaller tables gain from more lanes, also on 1 GiB pages (so not a
TLB effect). Solves/s, stream, 24 -> 40 lanes:
  h7 (THP)   1T  2.017 [2.017 2.017] -> 2.217 [2.217 2.217] (+10%)
             8T  15.433 [15.333 15.533 15.433] -> 17.067 [16.833 17.200 17.067] (+10.6%)
  h7 (1 GiB pages) 1T  2.017/2.050 -> 2.283/2.283 (+12%)
  h8 (1 GiB) 1T  4.067/4.000 -> 4.083 (equal; 32: 3.933/4.150, 48: 3.833)
             8T  26.733 [26.900 26.733 26.700] -> 29.100 [29.233 29.033 29.100] (+8.9%)
  h6         1T  1.117 -> 1.167 (+4.5%), 8T 9.37-9.73 -> 9.27 (about equal)
  h11 (1 GiB) 8T 197.833 [197.833 198.100] -> 190.933 [190.933 191.467] (-3.4%: stays 24)
  h7 1T, 12/16/20/24/32/40/48/64 lanes: 1.517/1.75/1.80-1.97/2.02/2.10-2.13/2.217/2.217/2.12
(1T: bench stream 10 60 1 L on one core of an otherwise idle L3 domain; 8T:
stream 10 30 8 L on one whole L3 domain; tables copied into THP memory
unless on hugetlbfs.)
