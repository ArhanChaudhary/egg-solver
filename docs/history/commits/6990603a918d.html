tables, cubie: Box<[T]> for the fixed-size cocsep tables and the symmetry list

The common "Box<[T]> instead of Vec for data that never grows" idiom (one word less per field, no capacity; the type says the length is fixed).

  • Cocsep: entries (153090), representatives and self_symmetries (one per class, 3393) and distribution (16 depths) are Box<[T]>. Cocsep shrinks from 112 to 80 bytes.
  • cubie::symmetries() returns &'static [Symmetry] (a OnceLock<Box<[_]>> of the 48 symmetries) instead of &'static Vec. representatives and self_symmetries are boxed slices of the final length, filled by class index (n_classes counts them). Pushing into a Vec and calling into_boxed_slice keeps a shrink path in the binary, because LLVM cannot prove capacity == length after the pushes: +654 bytes of solve::main, measured on 0d1a0e8. collect() over 0..N_COCSEP and vec![x; N] have constant lengths, so their into_boxed_slice folds away.

Tried and not kept (measured on 0d1a0e8, same folder, objdump):

  • distribution as [u64; 16]: Cocsep +80 bytes inline in main's frame (solve 0x980 -> 0xa00), so dozens of [rsp+disp8] become disp32: solve::main +1,138 bytes.
  • gen::Generator::derived as a Box<[_]>: it re-register-allocates gen's BFS relabel pass, for 8 bytes (neg/g1-generator-derived-box).

Hot code untouched (main ca820b6 vs this commit, built in the same folder, objdump with addresses normalized; $P/g1/asmcheck.py):

  • bench::stream_thread, share::Worker::rounds, bench::share_thread, bench's thread entry, and solve's pinned share code (the solve_all_pinned thread entry and run_pinned's frame) are instruction-identical, at the same 64-byte line offsets, with the same frames (0xfc0 / 0x98 / 0xfc0 / 0x700; solve 0x1000 / 0x190).
  • .text: bench 508666 -> 508858 (+192), solve 458602 -> 459130 (+528), gen 407498 -> 407306 (-192). .rodata and .data are unchanged.
  • Changed functions: RawVec::grow_one is gone (99 B). bench::main grows +291 and solve::main +636 (Cocsep::generate is inlined there). solve::main has fewer instructions (7512 vs 7536) at the same frame (0xf80): the bytes come from register and stack-slot allocation; on 4c74267 the same commit made it -118. gen's dfs::Prefix::build::{closure#1} is -16 (displacements of the smaller Cocsep).
  • Page offsets: solve's share code is pinned (rounds 0x310, the thread entry 0xdd0: unchanged). bench's hot loops move by -0x40 within their page (stream_thread 0x610 -> 0x5d0, rounds 0x1d0 -> 0x190), because code before them changed size. The whole series is timed below.
  • symmetries() is linked only into tests, build.rs and examples (not into bench, solve or gen). gen: the h0 (BFS) and h3 (dfs) tables are byte-identical to main's (cmp, gen compare), and gen's speed is unchanged (see below). Start-up: Cocsep::generate takes 12.6 ms on its first call and 6.65 ms at best of 10 (main, 1 thread). Not timed against main: the change is a few allocations fewer.
