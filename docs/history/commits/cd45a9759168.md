The packed cocsep table of the index path (`Cocsep::packed`) held 3
bytes per coordinate: class (12 bits), symmetry to the representative (6)
and corner depth (4). The depth is a class invariant (conjugation by a
symmetry keeps distances; checked for all 153090 coordinates), so it
moves to a 3393-byte table by class in front of the entries, and an entry
is 18 bits: 354 KB of entries instead of 448 KB.

Why it pays: the index path reads one entry per lookup, uniformly over
the table (an access histogram over 400 cubes is flat: 45% of the
coordinates take 50% of the reads), and every lookup also brings a
never-reused h11 table line into L2. In a cache model of one core
(cachegrind, 48 KB L1 + 1 MB 16-way L2, 40 cubes), the table lines are
78% of the lines inserted into L2 and the cocsep entries are their
victim: 20% of the entry reads miss L2 at 3 bytes per entry, 13% at 18
bits (-36% misses, ~183K fewer per cube). Calibration: the same data at a
4-byte stride (same code, +226K cocsep L2 misses per cube) measured
-1.6% at 1T layout-averaged (8/8 pairs negative).
