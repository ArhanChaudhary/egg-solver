# Development checks

[Documentation](../README.md) · [Safety](../safety/README.md) · [Publishing](PUBLISHING.md)

Run these commands from the project root. Build output follows `CARGO_TARGET_DIR` when set.

| Command | Purpose |
|---|---|
| `scripts/check.sh` | Formatting, Clippy, native tests and available backend checks |
| `scripts/miri.sh` | Miri unit-test catalogues and shared-search scheduling seeds |
| `scripts/stress.sh TABLE [set] [threads] [lanes]` | Compare solution lengths across search modes |
| `scripts/bench.sh TABLE [runs] [lanes] [threads]` | Repeated stream throughput measurements |
| `wasm/build.sh` | Build browser/Bun WebAssembly modules |
| `bun scripts/render-docs.mjs` | Regenerate HTML companions from Markdown |
| `bun scripts/render-docs.mjs --check` | Check that generated HTML is up to date |
| `python3 scripts/check-docs.py` | Check links, document/table structure and benchmark headline values |
| `python3 docs/reproduce/verify_bundle.py` | Verify documentation file hashes |

Miri requires a nightly toolchain with its Miri component. The runner documents its toolchain, log-directory and provenance options. Missing backend tools are reported as unavailable, not as successful validation.

The archived `scripts/experiments/pgo-solve.sh` is a historical experiment, not part of the release build or Pages deployment. [Performance history](../performance/README.md) records its scope and limitations.

## Editing documentation

Edit Markdown, run the renderer and documentation checks, then update `docs/MANIFEST.sha256` with the integrity tool's explicit `--update` option. Verify it again before committing. Generated HTML is committed for offline reading and regenerated by the Pages build. Archived raw outputs remain unchanged; new summaries link to them.
